## 2. 总体结论

**通用底座方向合理；当前主要风险不是少模块，而是跨能力协作时缺少少数确定承诺。** 三类用户的主线已具备，不能再以“平台通常都有”为理由补中心、脚本或固定层级。以下七项中，六项需收口契约或文字，一项应直接验证。

已覆盖且应保留：
- **对象与复用**：模型定义含义、模板组合默认配置、实例绑定现场、Profile 解释厂商映射；Unit 可选，Group 不复制资产或隐式群控（物模型 L84–91、L60–67；Unit L9–11）。
- **协议不等于用途**：采集参数／编码与观测、配置、目标、反馈分开；恒定新采样仍新鲜，页面刷新不刷新采样时间（能力 L23–36、L48–50、L77–82）。
- **规则计时不等于命令重发**：先判断数据与持续时间资格，再取首行；完成／等待／冷却不让位；未知不当假；冷却与完成记录跨重启保留。重发仅在同一请求的声明窗口内，由统一命令层执行（能力 L158–198）。本评审不退回“禁止任何重试”。
- **能力通用性**：通用契约统一支持项、来源、时效与原因；量化三种能力只用于适用对象。SOC、kW/kWh、PCC 与能源计算属于 EMS，容器和离散设备不被迫填数值能力（Unit L57–71；物模型 L73–82）。
- **真实性与数据使用**：独立反馈、局部质量、报警确认不等于恢复、保留边界及授权导出均已有验收（能力 L176–179、L290–309；总规格 L269–280）。不重复发明这些需求。

## 4. 七项重要发现（按用户影响排序）

### 1）P0 · 未定契约：无人登录时的自动逻辑，以谁的权限运行？

**证据**：总规格 L21–25、L200–202、L263、L364；能力 L136、L152、L177、L247；Unit L45–47。已有服务端鉴权、撤权停止后续重发和组合不越过成员保护，但未规定自动主体及范围计算。

**反例（输入→问题）**：交付人员甲为 Site A 配好自动规则，客户接手后停用甲账号；规则仍已启用。→ 不能判断应继续按项目授权运行，还是因甲停用而停止。再令一个 Unit 绑定 A、B 两台设备，操作员仅有 A 的权限却有 Unit 页面访问权：页面可访问不等于整体动作获准，但应按哪个对象集判定还不明确。

**最小补充**：用一张小表确定交互用户、规则／状态机、EMS 策略各自的运行主体与授权来源；列明查看、历史导出、报警处理、运行调参、控制、工程编辑及授权管理的对象范围。说明 Unit 对外操作与成员授权如何衔接、管理员最多能授予什么、撤权后新请求和后续发送如何处理；已发送动作不假装撤回。展示关系和页面参数均不得增权。

**需用户决策：是。** 尤其是自动控制是否使用独立的项目授权，以及授予 Unit 操作权的含义。**不加**新账号平台、SSO、复杂审批、租户体系或权限管理微服务；在既有账号与对象权限中定规则即可。

### 2）P0 · 条文冲突＋未定契约：“发布”与“应用”混用，关联配置缺少共同生效口径

**证据**：术语 L50–65 定义发布为不可变项目包、与部署／控制分离；能力 L137、L156 和总规格 L259 却以“发布 A”描述运行版建立。能力 L59 约束点位草稿不混用，L89 约束实例版本，L163 允许明确应用规则时按条件动作；总规格 L350–352 要求确定工程内容。

**反例（输入→问题）**：同时修改压力缩放、规则阈值和画面单位，只完成其中一项应用，另一项失败。→ 各项分别显示版本仍不足以说明哪个组合可以运行。另有启动请求等待反馈时改绑 Profile／反馈点：新映射的样本不能无说明地确认旧请求。“发布完成”到底只是形成包，还是已经改变现场，也会影响交付者操作判断。

**最小补充**：先统一现有按钮／验收中的保存、发布、部署、应用、启用含义；T13 明示建立运行 A 的那一步。再规定一次关联变更的依赖集合、生效条件、失败保留内容，以及在途请求绑定的目标／映射版本。可选择暂停受影响动作后切换，或拒绝不一致集合；无需承诺所有修改无中断或全项目大事务。

**需用户决策：部分需要。** 术语对齐不改变目标；允许怎样中断和处理在途请求需确认。**不加**版本恢复中心、升级合并、审批或新发布工作台。也不能用“部署不自动启动”否定能力 L163 已确认的“明确应用规则可能动作”。

### 3）P0 · 未定契约（文档已承认）：合法目标冲突时，不能只保证最终写口唯一

**证据**：能力 L152、L265–270；总规格 L311；Unit L85–91、L97。同级冲突已明确待定，不是本评审新发现的代码缺陷；T31-E 的最新数值目标规则不能代替所有策略优先关系。

**反例（输入→问题）**：两条同级规则在同一时刻分别请求同一转速 40、60，两者都合法；或者两个 Plant 各请求 80 kW，共享组只允许 100 kW。→ 唯一写口及限值能禁止乱写／超限，却不能确定采用哪个转速、两站如何分得 100 kW。让到达顺序获胜，就把未定业务选择藏进运行时。

**最小补充**：只为首版样板选择明确的冲突政策：哪些请求可取代、哪些拒绝、哪种保护优先，能源共享约束下采用哪种已支持分配规则，并给一组确定输入／输出。不强求平台支持全部政策。规则的首行资格与计时仍归规则自身；跨来源协调及请求执行归统一控制契约；能源目标分配属于 EMS。

**需用户决策：是。** 目标优先级、部分人工接管后的参与范围和资源分配属于业务选择。**不加**仲裁操作中心、任意优化器、请求队列产品或 HA 式运行模式选择器。

### 4）P1 · 未定契约：各输入“新鲜”，不必然代表可组成同一个现场判断

**证据**：能力 L31–32、L48–50、L63–65、L162–168、L301–304；Unit L69–71、L96–99；总规格 L257。时间来源、局部有效性和持续中断已覆盖，尚无多输入时间可比性的统一声明口径。

**反例（输入→问题）**：某动作要求液位足够且压力正常。液位来自 9 秒前，压力来自当前，两点有效期均为 10 秒；现场在二者之间已发生变化。→ 两点各自有效并不证明联合条件成立。相同问题会影响 PCS／BMS／PCC 能力组合及聚合。设备时钟偏移或迟到样本又会使“最新”与历史窗口归属出现不同解释。

**最小补充**：声明平台采集时间／设备时间分别用于排序、新鲜度、历史窗口的规则；迟到或倒退时间不能覆盖较新当前观测。对实际依赖多输入的动作／聚合，明确可接受时间差或明确接受“各自有效即可”的代价；不满足时给出不可用原因。按样板定参数，并在模拟中固定时间推进与到期顺序；无需所有数据同步采集。

**需用户决策：是，限场景阈值与容忍度。** 不是要求实现分布式时钟系统。**不加**强制采集组、通用流计算平台、无限历史重算或新时序运维中心。

### 5）P1 · 未定契约（明确留待走读）：不强制 Unit，就必须完成直接 Device 的换机路径

**证据**：物模型 L121–125；术语 L22；能力 L114–115；总规格 L260、L269。实际换机使用新 Device 身份、旧历史留给旧设备已明确，直接 Device 的改绑方案也明确尚待归纳。

**反例（输入→问题）**：一个温度传感器直接被画面、报警、规则引用，无 Unit。坏了换同型号新设备，新实例身份必须不同。→ 复用旧 ID 会混淆资产历史；新建 ID 后若只能逐项人工寻找引用，便破坏“换等价设备不重做应用”的交付任务。不能以补一层空 Unit 规避选择。

**最小补充**：在原设备绑定操作中，定义从旧设备到新设备的引用替换范围、兼容性判断及明确应用。至少说明画面、规则、报警定义／既有报警过程、历史和未完成命令哪些改绑、哪些保留原归属；已有历史和旧命令不搬成新设备运行态。是否一次迁移全部可迁引用，由用户确认。

**需用户决策：是。** 尤其是历史按单台资产还是业务位置连续查看，以及新设备控制授权如何重新确认。**不加**强制 Unit、资产全生命周期系统、换机中心或模板升级流程。

### 6）P1 · 未定契约：EMS 是专业化，但扩展提供者交付什么还不够明确

**证据**：术语 L40–44、L97；能力 L36、L333–355、L364；物模型 L97–107；Unit L59–69。已经禁止自由脚本，也允许已支持行业算法，但没有集中说明专业算法进入通用底座所须满足的 Interface。

**反例（输入→问题）**：EMS 模板需要按 BMS 分方向能力和跨 Plant 限制生成目标，通用求和／决策表不能替代该算法；换一版算法后仍用原参数和同名能力。→ 若仅校验“字段存在”，交付人员无法知道参数／方向／结果是否等价；若把特殊逻辑塞入 Profile 或网页，又绕回项目代码与额外写口。

**最小补充**：为首版能源算法与协议扩展各列一页以内的交付契约：支持的模型／版本与参数、输入用途／单位／时效、输出含义、不可用／缺口解释、模拟要求与依赖不满足时的行为。算法只能产出受约束目标／请求，不能另设协议写口；Profile 负责声明式映射，不承载任意行业算法。通用能力描述与 EMS 数值公式分别归属。

**需用户决策：业务支持范围需要；技术契约可另行设计确认。** **不加**热插拔框架、插件市场、包安装流程或第二个业务服务；版本化、随单 Go 服务固定交付已可满足当前范围。

### 7）P1 · 已覆盖／只缺验证：AI-only 制作与三条样板是否真能独立交接

**证据**：总规格 L62、L79–111、L127–131、L251–254、L267；能力 L238–246。规格已要求无需手改代码、实际绑定、离线运行和独立试用；证据表明示目标级待验证。本评审未核查仓库证据，不能据此断言没有实现或没有局部通过记录。

**反例（输入→问题）**：另一位交付人员要求只修改一个按钮文案，再把同一画面绑定第二台设备；生成结果视觉正确，却改变了原泵命令目标。→ 漂亮截图或页面可达都不能证明无代码交付。操作员离开 3D 视角后找不到报警设备，也不是通信测试能证明的事。

**最小补充**：不再加规格模块，执行已有 T05／T26／T31 的独立任务：记录是否完成、开发者介入、绑定错误、生成迭代／费用和操作员定位路径；交付者不能靠改源码救场。预先确认真实调用预算、失败判据及可接受工时，再逐项目登记证据。

**需用户决策：只需试验预算／合格线，不需重开已定路线。** AI-only 编辑、固定行业支持范围、无升级恢复中心均属已接受产品取舍；代价是生成失败时依赖再次生成，以及只承诺范围内的制作路径。**不加**手工编辑器、检查中心或通用低代码流程平台。

## 5. 精简 Module / Interface / Seam / Adapter 建议（概念层）

以下是责任归属建议，不是新增菜单、包目录、代码签名或微服务。保留单 Go 业务服务。Interface 包含语义、顺序、错误与生效条件，不只是字段；Seam 仅放在真实变化处。

| Module | Interface：调用者必须知道什么 | Seam 与 Adapter：哪里确实会变化 |
| --- | --- | --- |
| 工程定义与应用 | 稳定身份、类型／版本、依赖有效性、可覆盖范围、草稿与生效内容、受影响引用及在途请求处理 | 项目导入导出使用同一模型检查；不为每种对象另建一套应用流程 |
| 采集与观测 | 来源、业务值、用途、质量、时间、转换以及只读派生结果；不授予控制权限 | 协议通信 Seam；RTU 为当前必验 Adapter，仿真用于验证。Profile 是映射数据，不是任意算法 Adapter |
| 逻辑求值 | 规则资格／行序／持续／冷却／轮次，状态机转移；输出带来源的动作意图，解释为何提出或抑制 | 时间与观测输入形成可测试 Seam；仿真与现场应执行同一语义。命令重发不能藏在这里 |
| 受控执行 | 当前主体／目标、能力、控制权、互锁、请求取代、总窗口、尝试及独立反馈；统一真实目标与结果归属 | 同一命令 Interface 面向人工、规则、状态机、EMS；成员动作与协议写入由内部 Adapter 承接，不外露第二写口 |
| 行业能力与协调 | 输入契约、专业能力、共享约束、目标／缺口和结果；不自行鉴权或确认设备成功 | EMS 能力计算／分配是已有专业差异的 Seam；暂不假设第二行业算法或设计通用插件框架 |
| 应用与数据使用 | 按同一对象范围提供实时值、报警过程、历史／导出与可信操作结果；页面不自定权限或历史真相 | 生成的 2D／3D 页面是受限展示与操作 Adapter；后台定时逻辑不能借用页面身份存活 |

授权与对象身份是各 Interface 共同使用的约束，不由每个 Module 独立解释。优先把复杂度收在少数深 Module 内：调用者只提出业务意图，不自行处理通信重试、反馈归属与版本混用。若抽象删掉后复杂度没有回到多个调用者，就不值得增设。

## 6. 三个跨行业可证伪用例与优先级

三例验证已有通用能力，不新增协议、行业优化算法或产品模块；全部允许在正式 RTU 软件路径及行为模拟器中执行，真机与独立用户证据另签。

| 优先级／用例 | 固定输入与操作 | 可判失败的观察结果 |
| --- | --- | --- |
| P1 · 冷库温度监测（仅普通监测，不增加制冷控制） | Site 直接含两个温度 Device，无 Unit／EMS；A 数据恒定但持续采集，B 过期；更换 A 为新实例，并通过已确认方案改绑报警与画面；普通用户仅获 A 的历史范围 | A 被当过期、B 显示正常／零、要求能源字段、旧历史被改记给新资产、旧命令迁移，或导出夹带 B 数据，任一出现即失败；换机契约先完成发现 5 |
| P0 · 供水单元的规则与获准控制 | 一个 Unit 组合驱动和液位／压力；两行条件同时真，持续分别 30／5 秒；在 5 秒后行命中后保持条件，30 秒前行取得资格；注入无反馈、撤权、重启，再给有效状态；另注入各自有效但时间差超声明阈值的输入 | 持续前行提前遮蔽后行、前行已完成／冷却便让位、无声明重发、超时重建请求、重启清零冷却、撤权仍继续发送、超时记录被迟到状态补成成功，或超时差输入仍授权动作，任一即失败；先定运行主体与时间口径 |
| P0 · 光储充共享限值与专业化 | 同 Site 两 Plant 各请求 80 kW，共享组上限 100 kW；使用事先选定的分配规则和确定期望结果；让一 BMS 关键输入过期，保留可选表计正常；一成员已成功、另一成员无反馈；替换等价 Profile 后复测 | 超共享限值、违反预先选定结果、额定值冒充实时允许、净额掩盖局部 PCC 越限、整组重做成功成员、部分成功报整体完成、换 Profile 改变业务引用，任一即失败；核心无需增加 SOC 必填字段 |

先收口 1–3，再为 4–6 补最小契约；随后用以上反例及既有验收取证。第 7 项应尽早试做以暴露制作路线代价，但不得用其局部成功替代完整项目签收。结论不是“再造平台”，而是让已选的少数能力在同一用户任务中给出唯一、可解释、可验证的结果。
