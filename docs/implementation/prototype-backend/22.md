## Local implementation (2026-11-26)

- `POST /api/delivery/deployments` takes only `site` and `version`. Any client-supplied status or flag is ignored by design (the endpoint deliberately does not use the strict JSON decoder), because the record's state must be derived by the server.
- The server refuses unknown versions (404), tampered/missing-integrity versions (409) and a version whose engineering structure no longer matches the current project (`409 version_fingerprint_mismatch`, zero writes). The comparison is a structure fingerprint (node identity, type, mount position): connection addresses, poll parameters and descriptions legitimately change when the field is rebound, so they are not part of "does this version still correspond to this project".
- `configuration_applied` is set only after the server has re-derived the current project from storage and matched it with the version. `acquisition_restored` requires, for every configured channel unit, a verification record that passed under the current basis **and** current runtime health `healthy`; each missing unit becomes an explicit gap. `control_authorized` is always false: deployment never grants control.
- Status is `applied` (config applied, acquisition not confirmed) or `running` (both true). The record carries `id`, project/site, version ID, source version/fingerprint (from import evidence when present), actor, time, reason, apply evidence kind/reference, acquisition evidence (channel, device, health, verification time, level, basis) and the gap list.
- Records are append-only JSONL per site under the data directory, fsynced before the response; a create also appends an audit record (项目回退-style separate action `部署记录`). They are not derived from node points, so they never enter the project package export.
- Reading requires the caller to see the Site; listing returns records newest first for that Site only. Creating additionally requires the configure action.
- The delivery workbench 部署记录 tab now lists the real records with the three separate chips (配置已应用 / 运行中（采集已恢复） / 控制未授权), the acquisition gaps, and a "记录本次部署" button that calls the endpoint and shows the server-derived result. Preview keeps its own fixture rows.

## Explicit limits

- One channel/one device/one Site; multi-channel and multi-Site recording is covered by the API contract only.
- The minimal loop is local/target-instance only: no remote agent, no cross-site orchestration, no automatic start of control.
- Simulation evidence is a private loopback Modbus simulator; this is not field commissioning and not a claim of physical-device acceptance.
