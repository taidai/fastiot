## Local implementation / evidence — 2026-11-25

- `ScreenRenderer.vue` consumes the existing `screen.ts` / `screen_config.go` document in both `UiStep` and `LiveOverview`: fixed slots, per-block spans, declarative metrics/columns/tabs, scoped device/member/point data, explicit inherited provenance and unbound references. No iframe, second document format, sampler or per-page fake side-card arrays.
- Saves refetch the persisted document; local edits never mutate the saved baseline. Same-kind requests carry `target_versions`; every eligible target is checked before the first write. Missing sibling preconditions cannot overwrite an existing screen, stale saves return 409, and legacy writes cannot replace a structured version. A process-local API lock serializes compare-and-save; this is **not** a crash-atomic multi-node storage transaction. A write failure reports the completed count and failed target, not batch success.
- Structured references accept actual points of bound business devices and explicitly declared Unit members, with authorization checked independently. Cross-layer/unknown/non-point/script bindings and wrong fixed slots are rejected. Legacy screens retain the existing authorized-subtree contract without weakening structured validation or version checks.
- `DevicePanel.allowedTabs` is optional, defaults to both existing tabs, and resets a now-disabled active tab. It changes presentation only, not command/write/readback authorization; ticket 07 must retain this prop.
- Integration hooks: renderer slots `alarm`, `today`, `summary`; `after-side` keeps `HandoverPanel` outside the removable block catalog. Ticket 11 retains AlarmCenter/Handover lifecycle and the distinction between active-condition cards and unacknowledged bell count. Ticket 12 owns daily query/types/component; joint wiring pending its stable integration tip.
