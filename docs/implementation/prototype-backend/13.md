## Local implementation

- Reuses `StrategyStep.vue` and the existing decision document/parser/engine/sequence; no second rule engine. The baseline does not contain an `OwnRulesStep` component.
- Drafts carry durable revision identities; stale saves return 409. Publication accepts only the saved revision, does not enable control, and refuses publication while enabled. History restoration creates a new draft, not an implicit publication.
- Explicit `self` / `descendants` scope checks every point/action/readback reference. Unit members and mapped points on independent acquisition channels reuse existing business declarations; those relationships do not expand actor anchors. Inherited published rules are read-only and stop at the visible boundary.
- Physical execution uses the canonical manager's `Submit/Tick`, durable command journal, Profile commands and automatic/manual guards. Software variables reuse `Existing/Track/SetState` with durable pre-write intent, immutable terminal outcomes and fresh software acknowledgment; they are explicitly marked `confirmation=software`, never physical feedback. The rule sequence's additional constraints never promote a physical command outcome.
- Named commands resolve their complete fixed-write and parameter-default footprint for scope and output-ownership checks. Empty/default point types and keys normalize consistently. No multi-write command is reduced to one representative target for authorization.
- Rule-only JSON decoding rejects missing/null required numeric values, null optional timings/tolerances, invalid simulation numbers and overflowing durations; explicit zero and valid omitted defaults remain supported. Shared StateMachine action decoding is unchanged.
- Point OR groups cannot bypass the independent time-window constraint. Unreachable rows after an unconditional default are retained in the authored document and simulation traces, but omitted from the converted runtime table.
- Snapshot and WebSocket rule projections re-check current read visibility for draft/applied definitions, publication history and `lastCheck` evidence. Authorized definitions keep their existing shape; restricted data is marked explicitly. Persisted facts and internal `visibleNodes` are unchanged.
- `lastCheck` retains existing point-history storage and adds rule ID, source revision, execution identity, input target/time/quality and action command links for ticket16. `ruleAuthorization`, `lastExecution` and `lastCheck` are stripped from package reuse; draft/applied definitions and their revision remain.

## Explicit limits / acceptance differences

- The production adapter supports software variables, mapped Modbus declared commands and unmapped Modbus point commands. Allocator outputs, OPC-UA/MQTT outputs, and ramped rule outputs do not yet have a verified canonical rule adapter. Publication and enable refuse these targets with a target-specific reason; there is no physical direct-write fallback. Draft editing and pure simulation remain available. This remains an acceptance limitation, not full adapter coverage.
- Profile confirmation/deadline remains canonical. A row's additional readback/deadline can stop the rule sequence but cannot broaden Profile permissions or turn an Unknown command into success.
- No StateMachine, L3, unified execution-query or cross-derived-input safety implementation is included (tickets14/08/16/18 own those).
- Known full-suite baseline PumpHouse `unknown(clock_basis_inconsistent)` and bootstrap timestamp instability are not repaired or hidden by retries, skips or changed timeouts.
