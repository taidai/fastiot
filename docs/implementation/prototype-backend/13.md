## Local implementation

- Reuses `StrategyStep.vue` and the existing decision document/parser/engine/sequence; no second rule engine. The baseline does not contain an `OwnRulesStep` component.
- Drafts carry durable revision identities; stale saves return 409. Publication accepts only the saved revision, does not enable control, and refuses publication while enabled. History restoration creates a new draft, not an implicit publication.
- Explicit `self` / `descendants` scope checks every point/action/readback reference. Unit members and mapped points on independent acquisition channels reuse existing business declarations; those relationships do not expand actor anchors. Inherited published rules are read-only and stop at the visible boundary.
- Production rule execution uses the canonical manager's `Submit/Tick`, durable command journal, Profile commands and automatic/manual guards. The rule sequence adds its own delay/readback/deadline gate but never promotes or rewrites a canonical command outcome.
- `lastCheck` retains existing point-history storage and adds rule ID, source revision, execution identity, input target/time/quality and action command links for ticket16. `ruleAuthorization`, `lastExecution` and `lastCheck` are stripped from package reuse; draft/applied definitions and their revision remain.

## Explicit limits / acceptance differences

- The production adapter currently supports mapped Modbus declared commands and unmapped Modbus point commands. Legacy variable outputs, allocator outputs, OPC-UA/MQTT outputs, and ramped rule outputs do not yet have a verified canonical rule adapter. Publication and enable refuse these targets with a target-specific reason; there is no direct-write fallback. Their draft editing and pure simulation remain available. This is an acceptance limitation, not full runtime coverage.
- Profile confirmation/deadline remains canonical. A row's additional readback/deadline can stop the rule sequence but cannot broaden Profile permissions or turn an Unknown command into success.
- No StateMachine, L3, unified execution-query or cross-derived-input safety implementation is included (tickets14/08/16/18 own those).
- Known full-suite baseline PumpHouse `unknown(clock_basis_inconsistent)` and bootstrap timestamp instability are not repaired or hidden by retries, skips or changed timeouts.
