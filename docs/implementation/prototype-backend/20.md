## Package contract for later consumers (no ticket21–23 implementation)

- Existing `fastiot.project-package`, format version 2 is retained. A published release has `deliverable:true`, `source_version`, `source_fingerprint`, `manifest` and `integrity`. A live draft export is explicitly `deliverable:false`, has no source version, and never borrows the newest release ID. Legacy unsigned v2 input remains an existing compatibility path, not proof of delivery qualification.
- Ordinary `POST /projects/publish` takes `expected_fingerprint` from current preflight. Blockers always return 409 even with `confirm:true`; stale/missing fingerprints are conflicts. API engineering/permission mutations and inspection/publication share one configuration epoch, including authentication and referenced objects. A second captured fingerprint detects store edits outside that API epoch; it is not a general NATS transaction engine.
- `GET /projects/export?site=...&version=...` reads the saved artifact only. Snapshot records are `deliverable:false` and cannot be exported as published releases. Download rechecks every frozen node's permission, version identity, source fingerprint, artifact integrity and references. Mutable dependencies cannot silently change an existing artifact.
- `integrity` is the lowercase SHA-256 of Go `encoding/json` serialization with the integrity field empty. Manifest entries `node:<ref>`, `screen:<ref>` and `dependencies` hash their respective typed values the same way. Source fingerprint covers sorted original node configuration and exact dependency pins, excluding transport timestamps/origins and runtime. SIOT empty/legacy Point encodings are normalized through their existing JSON codec before hashing; command identities are not changed. Integrity detects changes, not authorship or cryptographic trust in a sender.
- Statistics describe this exact definition set: object nodes; physical/variable/calculation/virtual/aggregate point definitions; decision tables/state machines/capability rules; saved generated/structured screen definitions; exact Profile/industry pins. They are not device commissioning, runtime health or a claim of complete 1:1 prototype implementation.
- Structural screen layer/point bindings, DailyStats sources, unit roles, point maps, rule targets/readbacks, all machine versions' declared command devices, allocator/safety references use the shared ID→ref mapper. Missing/foreign references or missing dependencies reject export/publication, not silent empty counts. Recipient account lists are cleared and require explicit target-instance rebinding; no authority is copied.
- Notification journals/read state, rule execution facts, machine process/event ledgers, canonical command outcomes/IDs, runtime derived observations, grants, values/setpoints and credentials are excluded. Nested credential-shaped JSON is rejected. Publishing/exporting do not invoke runtime reconfiguration or emit control points. No importer UI, deployment engine or rollback expansion was added.
- Existing unsupported calculation/virtual-input rollback cases remain refused. Old recovery tests construct internal non-deliverable baselines but retain their real HTTP rollback/copy/upgrade assertions; that fixture setup is not a public publish bypass.
