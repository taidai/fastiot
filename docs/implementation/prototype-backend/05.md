## Implementation decisions

- Unbound business Devices now open the single-device workspace instead of BatchAccess. The original four stages remain. Empty persisted channels come from the authorized snapshot; an acquisition runtime with no points is not mistaken for an empty channel directory.
- Single-device `/modbus/{channel}/units/apply` uses `create_points`, `business_node_id` and `preview_version`. Dry-run returns the existing mapping differences plus the Profile-derived point creation plan and creates nothing. Apply rejects a missing/stale preview, occupied station, already-bound Device, unauthorized business reference or differing physical point semantics. It reuses `profilePointInputs`, point creation and acknowledged model persistence, not another driver or CRUD store.
- Address is now part of the mapping difference. Profile supplies address, format/function, scale/offset, unit, enum, read direction and required status. Explicit `required` wins; legacy `OPTIONAL` notes remain supported. An omitted JSON `read_only` defaults to true. L2 checks all required Profile points, not just command references; undeclared enum values fail quality verification.
- Saved models carry Profile content fingerprints and mapping versions including the acquisition configuration stamps. Profile content changes under the same ID, model map changes and physical mapping edits invalidate old manual verification. Existing command availability consumes the same invalidation gate; command execution semantics were not redesigned.
- Bound-model PUT rejects omitted/stale mapping versions and binding replacement, and cannot replace/apply a Profile instead of using the reviewed single-device path. Legacy unbound raw-station model clients retain their existing interface, but server-side change detection still clears old verification. The pre-existing batch/legacy apply interface is retained for ticket 06; its contract is not replaced by this ticket's single-device preview token.
- L1 uses the selected Profile's declared first point and existing Modbus transport, rather than assuming holding/input register zero exists. L2 consumes real runtime samples, validates Profile/mapping agreement, enabled state, freshness, valid values, acquisition stamp and enums. Both remain read-only.
- Automated records persist actor, nanosecond timestamp, level, result/reasons, Profile fingerprint and configuration basis. GET marks earlier evidence non-current after basis changes, including restart/profile substitution. A configuration change during verification fails the result. Automated verification remains separate from manual field sign-off.
- The verification stage is complete only for the latest current successful L2 record with no unsaved Profile/map change; applying a mapping alone cannot turn it green. Refresh restores this from persisted records. Ledger health cannot mark an unbound/incompletely mapped business Device healthy.
- No L3, bulk import or command feature implementation was added. Ticket 04's generic-create and L3 industry guards and ticket 19's authorization extraction are preserved.

## Verification limits / remaining scope

- This is software simulation evidence, not physical-device acceptance or M5 field sign-off. No physical device address or write was used.
- Single-device apply can populate an empty station or update the same binding. It does not take over another Device's occupied station or silently overwrite differing existing physical point configuration. Differences must be corrected explicitly.
- L2 evaluates recent real observations and their quality/configuration stamps; it does not manufacture a fresh sample or force all protocol reads synchronously in the HTTP handler. Before first acquisition it correctly fails.
- L3 execution, bulk/CSV behavior, command lifecycles, runtime/history redesign and comprehensive prototype pixel comparison remain outside ticket 05. Browser evidence is Playwright against the private real-Go fixture, not the inherited debug launch configuration.
- No original launch settings, credentials, permissions configuration, public issues, PRs, pushes or next-ticket work were changed or started.
