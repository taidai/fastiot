## Implementation decisions

- 新页面调用显式 `POST /access/batch/reviewed`，同样受 Configure 授权约束。此路由的应用必须携带匹配的 `preview_version`，不能通过删除 `reviewed` 等可选开关降级；请求中不存在该开关。旧 `/access/batch`、原始站号及 05 单设备接口保留各自契约，**不声称旧客户端也强制经过版本预检**。
- 在同一接入锁内先完成整批范围、重复设备、通道/站号占用、Profile 点位合法性及版本依据校验，再开始逐台应用。重复站号的所有参与行均阻断，不默认选择首行为赢家。可见设备若已通过不可见通道绑定，也只返回“设备已绑定”，不暴露隐藏通道信息。
- 版本依据覆盖 CSV、操作者、可见设备/通道和占用、Profile 内容、通道采集配置、物理点配置和已保存模型；不包含实时采样值。缺失/过期版本在任何写入前返回冲突；成功应用后的旧版本不能重放。
- 预览与应用复用 05 的 `profilePointInputs`、`applyProfile` 和模型保存；没有第二份 Profile 注册表或驱动。逐台预览返回当前匹配差异、待创建点位及缺失必需点，明确区分“将创建”与“已经采到有效值”。已存在原始点/绑定的站号不会被新批量流程接管。
- CSV 输入明确有界：JSON 请求体最多 2 MiB，CSV 最多 256 KiB、256 条设备记录，每字段最多 256 字节、每行恰好四列，重复/未知表头拒绝。UI 不再受 uni-app 默认 140 字截断；超限显示错误且不能导入。输入失效按实际文本变化处理，blur 同步 uni-app 节流事件的最新文本，迟到的相同 input 不会清除已返回的预览。
- 应用仍是逐台结果，不是整批事务：返回每行 mapped/blocked/failed 和实际 applied 数；UI 同时显示保存、阻断、失败数量。未知请求结果不显示全局成功，提示从后端刷新后重新预检。重试时已保存设备/占用站号被阻断，不重复创建。
- 批量页面从现有设备台账及逐台 `/verify` 历史恢复结果，限定在当前快照设备范围。L1/L2 按设备显式调用 05 的只读验证，展示最后一次对应级别的当前/失效状态、时间、操作者、失败原因。映射保存不是验证通过；修改映射后旧证据失效。没有新增批量结果数据库、L3 或命令功能。
- 预览模式仅兼容新路由和预览版本字段，沿用原有演示数据；它不作为真实验证证据。04 行业门禁、19 授权结构、02 上下文及 07/17 所有权边界未被改写。

## Verification limits

- 仅软件模拟证据，不是真机验收或 M5 签收；不触达物理设备，不执行 L3。
- 批量应用不是跨设备原子事务。覆盖了预检阻断与保存混合结果以及逐台通信失败；没有注入磁盘写满、NATS 中途断开等存储故障。应用失败的行必须看其实际返回并刷新，不推断整批回滚。
- 预览/被阻断的 CSV 草稿不构成新的持久化批任务日志；持久化的是既有设备模型、映射和逐台验证证据。重启验证读取同一来源，不依赖浏览器缓存。
- 版本比较是当前接入服务的乐观配置依据检查，不宣称能够对绕过此服务的外部存储写入提供跨进程事务锁。
- 浏览器夹具未配置行业包服务和画面，相关既有请求会返回 `packages_unavailable` / `screen_not_found`；没有把这些请求称为通过，也未为本票修改它们。旧 `modeling.browser.mjs` 仅同步新批量路由契约，本轮未运行其独立 5174 mock 夹具。
- 未诊断/修改共享 auth 浏览器过期问题，未放宽超时；未改原始 launch 配置、凭据或权限，未推送、创建公开 issue/PR，未启动下一票。
