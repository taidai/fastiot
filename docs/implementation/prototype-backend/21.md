## Local implementation (2026-11-26)

- Import evidence (`projectImportEvidence`) is persisted with the imported baseline version: actor, source package/version/fingerprint, target, time, result/reason, created node IDs and counts. An external valid package can be imported into an instance that never published it.
- Reference closure: aggregate owner and members, daily-stat points, screen bindings and raw point values (for example `powerSetpoint`) are remapped to the new instance's IDs. Imported rule drafts keep their numeric bindings; rule control is not enabled by import.
- Notification recipients are cleared on import. The imported rule cannot be published until recipients are explicitly rebound to eligible target accounts; an out-of-scope account is refused, an empty recipient list is refused, and rebinding creates no notification.
- Connection addresses are stripped, so the imported channel has no address and nothing polls. The existing `PUT /modbus/{id}` saves the new site connection; L2 verification against the private simulator produces the acquisition evidence saved with the import.
- Machine event/process ledgers, command outcomes, control grants and credentials are not restored.

### Defects found while driving the real browser (both fixed in this ticket)

1. **Rebind panel listed no channel.** Project packages strip connection addresses by design, and the running-channel listing (`buildBuses`) skips buses without an address. The panel therefore read "本次导入没有可重绑的通道" for exactly the channel that needed rebinding. The panel now lists the Modbus nodes of this import from the snapshot and only supplements them with running-channel information. This was the red case for the correction; the same browser script passes afterwards.
2. **Browser script selectors.** uniapp compiles `<label>` to `uni-label`, so the script's `placeholder`/`getByLabel` selectors could not find the address field even though the form opened correctly. The script now locates the field by its `uni-label` text; no product code was changed for this.

The browser fixture now wires persisted channel configuration the same way the real service does (`emsapi.Handler.Buses`).
