# 01: 真实登录与预览隔离

**What to build:** 正式模式使用真实身份，预览不覆盖真实令牌、不调用设备写接口；真实接口失败绝不回退演示数据。

**Blocked by:** None (can start immediately)

**Status:** implemented-local (verified locally; not published to GitHub)

## Acceptance criteria

- [x] 正式入口默认真实模式，预览需显式选择并标识。
- [x] 预览与真实令牌隔离，401/403 不触发模拟成功。
- [x] 浏览器测试验证登录、失效会话、模式隔离及无物理写入。

## Execution boundaries

- Reuse existing Go capabilities; keep the latest prototype UI and safe domain semantics.
- TDD: observe a failing behavior check before implementing; use real Go plus isolated storage/device simulators for acceptance.
- No push, public issue/PR/comment, real-device connection or physical write.
- Report tests actually run and remaining gaps; do not claim complete from mocks alone.

- Default URLs (including legacy `?live=1`) use the real API. Only document query `?preview=1` enables preview; a hash-route query cannot silently change mode. Login provides explicit full-page mode links, and all preview workbenches display `原型预览`. Preview login is memory-only, never reads/writes/removes the live token, and unresolved preview routes fail closed.
