## Local implementation (2026-11-26)

- Rollback validates before writing: version identity/structure, integrity digest (tamper and missing-integrity are refused), a re-loadable package built from the version nodes, and dependency/profile checks. A version or current project containing calculation or virtual-input nodes is blocked with `calculation_rollback_unsupported` / `virtual_input_rollback_unsupported`, naming each blocker's scope (`version`/`current`), node type and ID, marked retryable and stating that nothing was written.
- Before any write, the current configuration is frozen into a non-deliverable baseline version, saved and re-read. If that baseline cannot be saved or re-read, no configuration is written (`rollback_baseline_failed`). If the baseline itself is not restorable, the request is refused with `rollback_baseline_unrestorable` and zero writes.
- A failed write restores the pre-write baseline from the version file (deleting nodes created by the attempt) and answers `rollback_failed_recovered` with the baseline ID so the operator can fix the cause and retry; an unconfirmed recovery is `rollback_recovery_failed` and explicitly says the configuration cannot be trusted.
- Only configuration points are snapshotted: runtime points, secrets, `enabled`, machine `disabled` and the same exclusion set as package export are skipped, so rollback never replays commands, alarms, history, audit, notifications or control authorization.
- The delivery workbench's 版本回退 tab lists the real versions, confirms on a second click, shows the blocker list, the pre-rollback baseline and the "history/commands not rolled back" statement. Preview stays isolated.

### Fixture defects found while driving the real browser (test-only, all fixed here)

1. The "unsupported calculation" version referenced a plain `variable`, which is not a valid calculation input (only Modbus numeric points, calculations or virtual inputs carry kind/unit) — `missing_reference`. Replaced by a real Modbus holding-register point with unit `kW`.
2. Node deletion requires the current parent in the body (`invalid_json` otherwise).
3. The notification fixture used a non-existent rule ID and a fresh account whose anchors did not cover the Site (`notification_forbidden`). It now mounts a real decision-table node under the Site and uses the fixture admin as the recipient.
4. Deleting the calculation after publishing made the version list answer `source_forbidden` for a deleted reference. The scenario now moves the calculation out of the project (resource still readable), which keeps the version list readable and still triggers the unsupported-resource blocker.
5. The HTTP server bound `127.0.0.1` inside the container, so the mapped port was unreachable; the fixture now binds all interfaces (test-only).

None of these changed production validation, clocks, timeouts or assertions on the product behaviour.
