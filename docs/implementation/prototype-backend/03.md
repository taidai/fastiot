## Implementation decisions

- Reused `/templates`, `/nodes`, subtree copy, snapshot search and the existing member editor. No second CRUD store, project directory, protocol or preview-only implementation was added. Sites remain children of the authorized local project from ticket 02.
- Member PATCH now requires `members_version` (initially zero, read from snapshot point `easyemsUnitMembersVersion`). The existing node-write lock serializes read/check/save; accepted writes return the durable ID and incremented version, stale writes return `409 members_version_conflict`, and an omitted/negative version cannot bypass the check. Renaming without a members payload retains its existing contract.
- Copies retain independent identities and existing member reference rewriting: internal targets map to copied nodes; external targets become explicit unbound roles and are reported for rebinding. The source member edit version is not copied. Required gaps remain saveable drafts and are returned as `missing_required`.
- Legacy `group` creation now uses the same Area hierarchy check, closing the path that allowed a Device to become an arbitrary container. Ordinary point creation retains its existing contract.
- Creation/copy feedback stays visible in the ledger step after forms close. The member editor keeps its draft/version and save feedback across snapshot refreshes; it explains a conflict rather than overwriting another editor's changes.
- TopBar, session/authz contracts, industry gates and the inherited launch settings were not changed. `handler.go` has only the additional legacy-group hierarchy condition.
