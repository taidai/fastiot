## Implementation notes — 2026-11-25

- Reused `appapi/history.go` → `historyquery.Query` → existing runtime/SIOT adapters. No second history store. Point IDs, the authenticated project header and existing per-request object/export authorization remain authoritative.
- Prototype range chips and `自动 / 1秒 / 5秒 / 30秒 / 1分钟` controls are retained (default 5 seconds). Automatic reads raw observations. Explicit intervals request numeric window means, visibly labelled **窗口平均**; the actual window is never finer than the declared runtime sampling cadence. Requested and actual intervals are separate. Existing 5-minute/1-hour API clients remain supported.
- Responses expose actual interval, source, aggregation mode, retention policy, counts, truncation and duplicate-time-safe pagination cursors. Runtime retention is the real configured **count per point per observation/event kind**, not a fabricated 30-day duration. SIOT does not expose retention/cadence through its current adapter: those remain explicitly unknown, not inferred from timestamps or defaults.
- Raw invalid, stale, uninitialized, unknown-quality observations and quality events survive averaging with their original timestamps/kind; they never contribute to numeric means. A mean with any late contributor retains its late flag. Ordinary SIOT text retains the existing numeric-mean behavior (available in raw mode, not averaged into numbers).
- Charts never use received time as observation time, never join bad-quality samples, and break on gaps over 2.5 declared cycles. With unknown cadence, or for window averages, only actual points are drawn rather than implying continuous measured data. Table rows show quality reasons, received time, timestamp basis, late flags, bucket/sample-count labels and missing-interval notices; no synthetic samples are inserted.
- Pagination replaces one bounded page (2000 rows), retaining the original time window. CSV uses that same successful object/window/granularity without the page cursor; the backend caps the complete export at 10000 rows including quality evidence. CSV also carries timestamp basis, lateness, actual interval and retention metadata. No export action means 403, even for viewers/operators; a project header never widens object scope.
- History remains at `/pages/history/index?point=<stable-point-id>`. `navigateTo` from metrics/devices/alarms preserves the originating page/layer for Return. Ticket 09 owns LiveOverview/FlowScene; this ticket does not edit those entrypoints or `session.ts` runtime handling. The existing history page/table/trend share the 01/02 authenticated request client and project invalidation fences.

### Limits / explicitly explained differences

- No claimed 30-day retention: runtime storage is count-bounded; SIOT retention and cadence remain unknown until that adapter exposes policy. Matched counts describe retained data, not records already evicted. The runtime cap applies separately to its sample/event queues; the event queue can also contain late observations.
- Explicit seconds/minutes are window means, not invented regular raw samples. Means and unknown-cadence series use dots rather than pretending continuous measurement. The additional metadata and pagination controls explain these safety differences from the fixed prototype demo; this is not a blanket all-states 1:1 visual claim.
- Verified in self-contained Playwright, not the Browser pane. The inherited launch configuration was neither used nor changed/committed. Other viewport/theme combinations and physical devices were not tested. The fixture has no device clients or physical writes; this is software evidence, not field acceptance.
- LiveOverview/FlowScene entrypoint ownership remains ticket 09; other alarm workflow enhancements remain their own tickets. No additional tickets, credentials/config changes, push, issues or PRs were started.
