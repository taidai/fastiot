## Implementation decisions

- The real device panel opens `OperationDrawer`, containing declared Profile commands and independent, explicitly confirmed manual-takeover/resume controls. Arbitrary point writes were removed from this drawer. The existing generic value endpoint rejects outputs explicitly mapped by a saved Profile (`declared_profile_command_required`); legacy unbound point workflows are not replaced.
- Command execution and GET/list results reuse the existing `command.Manager`, never another command engine. Every request still passes role/action, channel/point/business-object scope, industry dependency, current mapping/verification, parameter and safety checks. Model availability exposes authorization/offline/interlock reasons. A declared boolean parameter remains binary even when mapped to a numeric register.
- Request identity compares Actor, DeviceID, CommandID and Source explicitly. New parameter fingerprints use deterministic standard JSON, including point/value and confirmation/fallback options; no delimiter-based ambiguity. Historical fingerprints are not rewritten: unambiguous legacy requests remain queryable/idempotent, ambiguous legacy parameter names fail closed.
- The same `commands.jsonl` now journals and fsyncs accepted intent **before** protocol dispatch. A single manager lock serializes durable lookup/reservation/dispatch. The display preload is bounded to 500 requests, but no longer truncates durable identities. Cold IDs are looked up in that same journal after memory eviction or restart. Missing/corrupt/unwritable storage prevents a new action; post-dispatch persistence failure leaves canonical `unknown`, not a fabricated success or authorization to retry. Unfinished restored intents become unknown and never replay.
- Named safety refusals are `rejected`; physical refusal is `failed`; acceptance, submitted-without-confirmation, confirmed and unknown remain distinct. The UI retains the generated request ID across a lost response/reload; its query button only issues GET. There is no automatic physical resubmission.
- Each submitted command retains its deadline and actual confirming observations. Profile `readback_tolerance` defaults to exact equality and propagates to fixed and parameterized readback. Confirmation requires the correct target's good, finite, new observation and arrival within the deadline. Missing, invalid, stale, old, future, wrong or unavailable feedback cannot confirm.
- Timeout retains monotonic elapsed-time semantics; audit wall-clock evidence must independently fit the same submission/deadline window. A real test caught a wall-clock jump: deadline `05:16:41.761323544 m=+14.165383615`, observation `05:16:42.834311610 m=+13.925269916`. Monotonic order alone would have confirmed evidence serialized after its deadline. Conflicting evidence is now rejected and becomes `unknown` with `clock_basis_inconsistent`; no machine clock, auth expiry, or timeout was modified. Timely receipt processed later still confirms when valid.
- Takeover/resume reuses `/nodes/{declared-output}/manual`, its independent WriteValue permission and the existing `easyemsManual` state consumed by decision execution, allocation and the shared command guard. It pauses that output's related ordinary automatic control, not safety protection or every device process. Explicit mode intent and normal HTTP result are audited. Generic configuration PATCH cannot grant this authorization. Navigation/reload never changes it.
- Ticket 17's `allowedTabs` defaults and tab-selection behavior are preserved. The drawer teleports to its current page root, retaining theme inheritance while escaping filtered screen-block containing boxes; it is viewport-right rather than clipped inside a screen block.

## Limits / retained boundaries

- This is software simulation evidence, not real-device acceptance or M5 sign-off. No physical address/device, inherited debug launch, original checkout, credentials, permissions, push, public issue/PR or other ticket implementation was used/changed.
- The durable journal is append-only and has no idempotency TTL. Cold lookup is linear in journal length and startup scans it with a bounded display preload. Disk growth and fsync latency are deliberate safety costs; exhausted/unavailable storage blocks control rather than silently discarding identities. One runtime owns the store; multi-process journal coordination is not introduced.
- IDs already deleted by older versions' retention, deliberate loss of the entire store, or unsupported filesystem durability cannot be reconstructed. This change preserves retained historical identities and all newly journaled identities; it does not invent missing pre-upgrade history.
- Browser restoration tests restart the command owner over the same persisted log, not the entire host or a physical controller. Existing store/history restart tests remain in the full suite. A process restart never provides new device confirmation for an unfinished command.
- The old standalone mock `overview-browser-check.mjs` was not rewritten or claimed passing: it still references generic-write controls and older project/chrome fixtures. This ticket's real-Go browser test verifies the new declared-operation path. Broad prototype pixel comparison and unrelated preview-suite repairs remain outside 07.
- Existing unmapped generic point operations and point-write compatibility states are retained. No L3, batch/Profile-apply redesign, new rule/state-machine executor, or today-runs projection was added. The shared auth fix and ticket 17 renderer changes came only from the parent-approved merge.
