## Local implementation / truth boundary (2026-11-26)

- `GET /api/overview/executions`: existing project-header enforcement plus current identity, explicit layer, IANA timezone/date, source filter, bounded limit/offset. Sort uses source time and stable identity. `total` counts visible retained rows; `execution_count` excludes checks without captured execution identity. Neither claims a complete day's history.
- Machine rows come from the existing per-event durable ledger. Rule rows use the existing reservation/check producer: `ruleExecutionFact` schema 1 stores historical source document, original scope, reservation time and immutable content-addressed reports. A persisted per-execution sequence selects progress without using a later wall-clock value to rewrite an earlier report. No new execution loop, polling engine, or command path.
- Deduplication uses the original rule reservation / machine request identity. Reservation without outcome remains unknown. Canonical command status is a separately labelled lookup, never a replacement for the historical process result. Notification creation, per-account reading, software acknowledgment and device readback remain different facts; this query exposes no account read data.
- Current authorization rechecks historical source bindings, inputs, action targets, command writes/readbacks/observations and original rule receipt scope. A moved input or source mount cannot make previously out-of-scope evidence public. In addition to local/subtree source nodes, readable ancestor sources qualify only through recorded targets (check targets/allocation members, machine command references and canonical writes). Current tree/member scope resolution is reused; current draft/Profile rebinding does not replace historical target identity. A mixed execution is counted once and only matching actions/targets are returned; unrelated ancestor events, sibling actions and parent-scoped notifications are excluded from a child query. Raw capture points are removed from snapshot/WS (node and edge points) and excluded by the shared reuse/export runtime-point filter.
- Existing `ScreenRenderer` Today slot mounts the new query component only in live mode. The existing shared preview and 总览／设计／交付 navigation remain intact; no new dashboard. Queries run on context/filter changes or explicit refresh, not on an additional timer.

## Explicit limits

- No pre-capture backfill is invented. Legacy rule checks are latest-only and uncounted; missing execution/action IDs remain absent. Machine pre-ledger history is unknown. Capture records survive process restart but remain attached to their source node; deleting the source removes this query's coverage. There is no archive service, new TTL policy, or full-day completeness claim.
- Pagination is over the currently authorized retained set, not an immutable multi-request snapshot. A refresh/context change resets the page and discards late responses. Ancestor inclusion requires a recorded target association; legacy transport points without a historical business association are not reassigned through today's Profile mapping. Cross-layer free-form diagnostics are withheld in the child projection, while the original overall process state is preserved.
- Only software acknowledgments, private local notification creation and isolated stores were exercised. No physical device, real output, external message, credential change, push or GitHub publication. Test counts do not establish complete prototype 1:1 or field acceptance.
