## Implemented scope

- The bell counts **unacknowledged active occurrences across the authorized scope**, including design/delivery consumers of the shared store. The overview's **本层活动告警** is the current subtree/device subset and retains acknowledged but still-active conditions. Failed runtime queries clear stale alarm projections and display the query error.
- AlarmCenter shows observation count, original occurrence time, handling actor/time/note, unknown observation state, and occurrence-specific process history from the existing `/alarm-events` API. It uses the existing stable device/point identifiers for locate/history10; a changed point mapping disables navigation rather than jumping to a different device. No manual recovery action was added. Closing still requires a resolved occurrence and the existing authorization.
- Real normal observations resolve the existing occurrence. A subsequent abnormal observation creates a new occurrence ID under the same condition key, without reusing the previous acknowledgement. **`count` means distinct abnormal observations within an occurrence, not the number of raised/retrigger events.** The UI labels it `异常观测 … 次`.
- The existing alarm engine is restored from highest-revision records in **the existing `alarm-events.jsonl`**, including handling, recovery/history and observation count. Replay is idempotent, emits no actions, and marks active inputs unknown until fresh observation. Unreadable evidence yields 503, not a successful empty alarm list.
- Continuous observations retain the original **OnChange does not notify** contract. A separate checkpoint callback persists count updates to the same journal. Duplicate source timestamps do not increment count, emit a checkpoint, or notify. Checkpoints are excluded from process history and raised statistics.
- At **1024 checkpoint writes**, atomic compaction retains every real lifecycle transition and only the highest-revision checkpoint per occurrence. Additional checkpoint replay overhead is bounded by the uncompacted batch plus one retained checkpoint per occurrence; this is **not** a retention policy for real lifecycle history. Appends check write, `Sync` and close errors. Compaction prepares/syncs/closes a temporary file before rename; failure leaves the old journal intact and reports evidence unavailable. No separate alarm store was introduced.
- Handover reuses the existing scoped GET/PUT and durable store: actor/time come from the server. The component resets on layer/project/session changes, invalidates callbacks on unmount, and fences both cross-layer saves and an older same-layer GET completing after a newer save.
- LiveOverview edits are limited to alarm subset/label/action/history wiring. Daily statistics, screen rendering, authentication, industry gates and authorization policy were not rewritten. Ticket17 can consume `layerActiveAlarms` in its alarm slot; HandoverPanel remains independent.

## Remaining limits

- This is software/simulator evidence, not physical commissioning, site sign-off or a power-cut durability test. The isolated fixture never connects to real equipment.
- Legacy journal entries did not persist observation counts. Missing old counts cannot be reconstructed; they display as unrecorded and subsequent counts reflect available recorded observations. Entries without occurrence identity remain explicitly incomplete in the existing history/statistics contract.
- Compaction bounds redundant observation checkpoints, not the retained true-transition history. It adds synchronous persistence I/O for new abnormal observations; no high-frequency throughput claim is made.
- The browser restart control rebuilds the runtime; the separate Go HTTP test additionally reopens the metadata server/storage. Cross-layer and same-layer browser response races are covered; project/session fences also reuse the separately tested shared request contract.
