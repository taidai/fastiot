## Implementation decisions

- `GET /api/projects` is an authenticated directory declared in `internal/authz/routes.go`. It projects the existing durable root, rather than creating a second project store or treating `projects/sources` (versioned Sites for reuse) as a catalog. One local runtime returns one project, containing zero or more Sites.
- The root ID is the stable **local project** identity; authorization anchors remain `scope_root_ids`, not project identities. `runtime: {kind: "local", root_id: ...}` describes the local association, not a new deployment record or globally registered runtime identity.
- Existing immutable versions are Site-scoped. The directory says `version_scope: "site"` and returns each visible Site's latest version, or `null`; it does not invent a root-wide published version. Dependencies and Site metadata are projections of authorized objects, not an unrestricted project export.
- Live business requests carry `X-Fastiot-Project`. Before dispatch, Go verifies the durable root and intersects anchors with that root; existing action and target checks still apply. A Site ID or foreign project yields `409 project_context_mismatch`. Legacy clients without this header retain the existing single-runtime resolution and object authorization contracts.
- All three workbenches use one live context. Only the user-scoped project/layer preference is stored; a fresh authorized directory and snapshot validate it after refresh/relogin. Account changes clear memory, and successful login recreates the page stack. Site selection in delivery follows the shared layer; only an explicit Site change changes that layer.
- The shared API client fences late reads, writes and binary evidence downloads by context generation, including A→B→A. Already-sent writes are **not cancelled or replayed**: their original target/header remains fixed and the switch confirmation tells the user to verify results in the original project. Old responses cannot report success in the new context.
- Project switching always explicitly confirms discard, including editors without dirty tracking. Cancel keeps the draft; confirm clears scoped data and recreates the workbench, rather than reusing its local editor state. Menu Enter/Space, arrow keys and Escape are supported; releasing the opening Enter cannot also confirm the discard dialog.
- Ticket 01 remains intact: real mode is default, preview is explicit and independent, preview neither reads live credentials nor sends real API requests, and preview reload resets its baseline.

## Verification limits / remaining scope

- These are self-contained Playwright browser tests, **not Browser pane verification**. The inherited launch configuration was neither used nor committed.
- Cross-project dirty/discard and delayed-response browser races use an explicit two-context HTTP fixture. The production Go runtime deliberately exposes only its one determined project; no artificial multi-project runtime or cross-runtime orchestrator was added. Real Go covers one project with multiple Sites, scope rejection, persistence and revision conflicts. Concurrent editing was tested via two real HTTP sessions, not two UI editor windows.
- No new global cross-runtime project identity, root-wide immutable version, project-creation workflow, deployment registry, statistics/device logic or CRUD redesign was included. Existing Site versions and revision contracts remain the source of truth; later tickets own the corresponding workflows.
- No physical-device connections/writes, public publication, credentials changes, launch-settings changes, or follow-on tickets. Software/fixture evidence is not field acceptance.
