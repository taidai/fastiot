# 以最新版原型为目标的真实后端接入规格

状态：已按用户 `/implement-spec 并行实现所有` 开始本地隔离实施；25 张本地执行票按依赖推进。尚未创建 GitHub issue。

## Problem Statement

用户希望把已经确定产品形态的最新版玻璃磨砂原型，变成由真实现场数据和持久化工程资产驱动的 FastIOT 应用。交付人员应能在设计六步中建立工程、完成接入与策略、配置客户画面并交付；终端客户应能在总览里看清现场、处置告警并进行受控操作。

当前实现存在三类问题：

1. 为了迁就已有接口，部分页面增加了原型之外的控件和后端缺口说明，或者改变了原型交互。测试通过并不意味着与原型一致。
2. 默认展示的预览数据来自不同状态模型。选中项目虽然可共享，但设计修改、总览画面、项目包统计、导入进度与证据仍不能保证来自同一份工程事实。
3. 真实后端已经有大量可复用能力，但原型要求的统一项目上下文、完整今日统计与执行查询、部署记录和持续聚合采样等闭环尚不完整。不能靠填演示数字或把“已接受请求”展示为“已完成”补齐。

目标不是“把演示开关改成网络请求”，也不是再建一套后端，而是在保持原型产品形态的前提下补齐必要业务契约，使所有读写、权限、运行结果和交付证据可验证、可追溯。

## Solution

以“总览 · 玻璃磨砂”“设计 · 玻璃磨砂”“交付 · 玻璃磨砂”的最终可交互版本作为界面与流程基准，沿用 uniapp、Vue 3、TypeScript 和现有 Go 后端。

三个工作台使用统一的项目身份、对象身份、工程版本、画面定义和运行数据来源。原型预览作为隔离的验证场景保留；正式运行默认连接真实后端，不得在接口失败、无数据或无权限时回退到演示数据。尽量由同一套页面组件消费两种数据来源，避免长期维护两套行为不同的总览。

验收包含两个独立但必须同时满足的条件：

- **界面与交互一致**：原型已定义的页面、弹层、布局、文字层级、入口、操作顺序及失败反馈没有被接口实现反向改变。保留用户明确追加的总览／设计／交付导航。真实对象名称、观测值、权限及必要安全提示可以随事实变化。
- **真实业务闭环**：通过真实 Go 服务完成读取、保存、刷新恢复、权限校验、模拟、发布、回读、导入和交付状态验证；浏览器不得自行编造执行成功、部署完成或实测值。

原型中的模拟失败、模拟身份及设备场景控件是验收驱动方式，不是正式系统的权限绕过入口。真实模式通过真实错误、测试模拟器和受控故障注入触发等价结果。原型明确标注的占位工具页不自动扩展为未定义的新业务模块。

## User Stories

### 项目上下文、身份与工作台

1. 作为交付人员，我希望在顶栏选择我有权访问的项目，以便总览、设计和交付始终描述同一份工程。
2. 作为交付人员，我希望项目、Site、业务单元和设备使用稳定身份，而不是靠名称匹配，以便重命名和同名对象不会串数据。
3. 作为交付人员，我希望切换工作台保留项目和对象上下文，以便不必重新寻找正在配置的设备。
4. 作为交付人员，我希望切换项目时未保存的工程修改被明确处理，以便草稿不会丢失或被应用到另一项目。
5. 作为交付人员，我希望保存后的工程在刷新页面、重新登录及服务重启后仍然存在，以便工作成果不依赖浏览器内存。
6. 作为交付人员，我希望多用户同时编辑时得到明确的版本冲突提示，以便不静默覆盖其他人的修改。
7. 作为终端客户，我希望只看到授权范围内的现场、数据和操作，以便界面不会泄露或控制其他对象。
8. 作为管理员，我希望正式模式和原型预览明确隔离，以便预览登录、模拟状态和演示命令不会进入真实实例。
9. 作为交付人员，我希望依赖 EMS 的项目在行业包不可用时得到明确门禁，以便不会打开一份缺少必要能力的工程。
10. 作为交付人员，我希望不依赖 EMS 的普通 IoT/SCADA 工程仍然可用，以便行业能力不是底座的必选条件。

### 总览与可信观测

11. 作为终端客户，我希望点选现场、区域、业务单元或设备时看到该层的 SCADA 画面，以便视图范围与所选对象一致。
12. 作为终端客户，我希望未绑定设备不冒充在线设备，也不产生运行数值，以便知道哪些对象尚未接入。
13. 作为终端客户，我希望指标显示正确名称、单位、质量及有依据的更新时间，以便判断这一屏数据能否用于操作。
14. 作为终端客户，我希望无值、断线、过期、无权限和查询失败得到不同反馈，以便不会把缺失误读为零或正常。
15. 作为终端客户，我希望通信状态、运行状态和维护状态保持区分，以便“在线但停机”不会被合并成一个绿色状态。
16. 作为终端客户，我希望工艺图或能流从当前层的拓扑与绑定取值，以便切换项目后不会仍显示上一项目的设备。
17. 作为终端客户，我希望最近数据表和变化记录来自当前层的真实观测及事件，以便能追溯数值变化而非看到固定演示行。
18. 作为终端客户，我希望今日电量和运行时长由后端按现场统计口径计算，以便关闭浏览器后统计仍然连续。
19. 作为终端客户，我希望通信成功率和数据新鲜度说明对应窗口及时间依据，以便不把历史累计或接收时间当成当前健康情况。
20. 作为终端客户，我希望今日执行包含触发、完成、跳过、失败和结果未知及其原因，以便区分自动化判断与设备实际执行结果。
21. 作为值班人员，我希望交接留言关联正确现场层级、操作者和时间并持久保存，以便下一班获取可信交接内容。
22. 作为终端客户，我希望外观设置和屏幕适配保留原型体验，但不改变数据与权限语义，以便设备差异只影响展示方式。

### 历史与告警

23. 作为终端客户，我希望从指标、设备和告警进入对应历史视图，并返回原先对象，以便不丢失现场上下文。
24. 作为终端客户，我希望按原型提供的时间范围与粒度查询历史，以便无需因为接口能力不足改用另一套页面。
25. 作为终端客户，我希望历史响应说明实际粒度、数据来源、保留期及截断情况，以便明确查询结果是否完整。
26. 作为终端客户，我希望曲线在断线、失效和超过采样依据的缺失段处断开，以便图形不会制造持续观测的假象。
27. 作为获授权用户，我希望导出的 CSV 与当前对象、时间和质量规则一致，并受数量限制，以便导出不绕过查询权限。
28. 作为终端客户，我希望告警角标和本层告警列表分别反映全授权范围与当前子树，以便总量和局部情况都能解释。
29. 作为值班人员，我希望接手告警只改变处置状态，不自动恢复设备或清除故障，以便人员动作与现场条件分开记录。
30. 作为值班人员，我希望告警恢复和再次触发保留稳定身份、次数与历史，以便不会产生无法关联的重复卡片。
31. 作为终端客户，我希望从告警准确定位设备和相关点位历史，以便诊断链接不跨到其他对象。

### 设备操作与安全

32. 作为获授权操作人员，我希望操作抽屉只提供设备能力契约支持且当前允许的命令，以便不能用普通写点入口绕过约束。
33. 作为获授权操作人员，我希望命令参数在后端校验范围、类型、状态与对象权限，以便修改前端请求也无法越权。
34. 作为获授权操作人员，我希望每次命令有可查询的请求身份和结果，以便网络中断后仍能查明执行情况。
35. 作为获授权操作人员，我希望重试同一请求不会重复执行现场动作，以便超时重试不导致重复启动或重复写入。
36. 作为获授权操作人员，我希望回读成功、仅已下发、拒绝、失败和结果未知被明确区分，以便不会因按钮点击而误认为操作完成。
37. 作为获授权操作人员，我希望回读校验使用命令之后的有效观测、声明容差和截止时间，以便旧值或缓存反馈不能确认新命令。
38. 作为值班人员，我希望人工接管与恢复自动控制具有独立确认和审计，以便切页、刷新、登录或通信恢复都不会改变控制授权。

### 设计六步：工程、接入与策略

39. 作为交付人员，我希望从空白、供水泵房或储能模板创建工程骨架，以便模板复用不带入旧现场地址、凭据及运行状态。
40. 作为交付人员，我希望新增、复制、搜索和选择台账对象遵循合法层级，以便设备不能错误地成为任意容器。
41. 作为交付人员，我希望业务单元的必需／可选成员绑定持久保存并说明缺失影响，以便结构存在不等于能力可用。
42. 作为交付人员，我希望按型号→通道→点位→验证完成接入，以便每一步使用同一个 Profile 来源。
43. 作为交付人员，我希望型号、地址、类型、倍率、单位、枚举、读写方向和命令参数约束有明确版本，以便换型号后旧映射不会被错误沿用。
44. 作为交付人员，我希望 Profile 匹配和应用先给出差异与阻断原因，再明确保存，以便预检不会意外改变现场连接。
45. 作为交付人员，我希望批量接入和 CSV 导入逐台检查站号冲突、必需点缺失、离线与部分失败，以便“批量成功”不能掩盖单台失败。
46. 作为交付人员，我希望 L1 连通和 L2 必需点验证为只读，结果带时间、操作者与原因，以便验证可复查且不会误写设备。
47. 作为交付人员，我希望 L3 只对 Profile 明确允许的安全点，经额外权限和显式确认后执行，以便设备验证不会成为任意写入通道。
48. 作为交付人员，我希望按四段式编辑决策表的条件组、持续时长、时间窗与动作序列，以便原型中的规则无需改写为自由脚本。
49. 作为交付人员，我希望策略显式支持本对象／含下级及可追溯继承，以便策略不默认越过声明范围。
50. 作为交付人员，我希望规则模拟逐行解释命中、跳过与等待原因且不写设备，以便能在发布前验证逻辑。
51. 作为交付人员，我希望规则保存草稿、发布、启用自动运行彼此分离，以便保存工程不等于允许现场控制。
52. 作为交付人员，我希望状态机定义、守卫、事件模拟与过程状态可保存和发布，以便过程记忆不依赖浏览器。
53. 作为交付人员，我希望状态机执行仍通过统一命令、授权和回读机制，以便不能通过状态转换绕过设备安全边界。
54. 作为交付人员，我希望聚合定义在后台持续生成有质量和时间依据的聚合点，以便没人打开页面时历史和策略也能使用它。
55. 作为交付人员，我希望窗口聚合标明窗口和滞后，保护与联锁不能绑定滞后的窗口值，以便展示统计不冒充实时安全输入。
56. 作为交付人员，我希望计算点、虚拟输入和实测点的来源始终可区分，以便模拟输入不被当作实测回读。
57. 作为交付人员，我希望原型中的站点工具入口与返回路径保持一致，以便底层能力可以从原有工作流找到，而不是增加另一套导航。

### 配界面与跨页一致性

58. 作为交付人员，我希望按封闭块目录、声明式绑定和槽位配置画面，以便不需要自由画布或手写脚本。
59. 作为交付人员，我希望未保存修改只影响当前配置预览，保存后客户总览立即消费同一份画面定义，以便预览与客户看到的页面不分叉。
60. 作为交付人员，我希望未配置的层继承最近祖先的定义并标明来源，以便默认行为可解释且子层修改不覆盖父层。
61. 作为交付人员，我希望“应用到同类层”受对象范围、节点类型和版本冲突校验，以便批量应用不会错误覆盖无关层。
62. 作为交付人员，我希望画面绑定随项目包导出、导入和重绑后仍指向新实例的正确对象，以便复用不会读取或控制旧现场。

### 交付、部署与审计

63. 作为交付人员，我希望交付页的对象、点位、策略、画面和依赖统计直接来自当前工程版本，以便设计修改与包内容不会各说各话。
64. 作为交付人员，我希望预检返回逐项通过、注意、阻断、原因、对象和修复入口，以便可以按原型定位问题并重新检查。
65. 作为交付人员，我希望原型发布动作在阻断未消除时不能产生“可交付版本”，以便确认按钮不能绕过交付门槛。
66. 作为交付人员，我希望发布版本不可变、依赖有确切版本或指纹、导出不携带凭据和运行状态，以便跨实例交付可重复且安全。
67. 作为交付人员，我希望导入前验证完整性、引用和依赖，失败后不留下可运行的半份工程，以便导入失败可以安全恢复或重试。
68. 作为交付人员，我希望跨实例导入后先完成现场重绑与必要验证，再进入运行检查，以便旧地址、旧命令和旧控制授权不被恢复。
69. 作为交付人员，我希望部署记录能证明某版本应用到了哪个现场运行实例，记录人、时间、结果和失败原因，以便“运行中”不是浏览器手动推进的标签。
70. 作为交付人员，我希望页面区分配置已应用、采集已恢复与控制已授权，以便部署成功不被误认为已经投运。
71. 作为交付人员，我希望版本回退先校验可恢复性并保存当前基线，仅恢复工程配置，以便运行历史、告警、审计及命令不会倒退或重放。
72. 作为管理员，我希望账号、角色、动作白名单与对象范围共同决定权限，以便前端矩阵与后端实际许可一致。
73. 作为管理员，我希望权限演练只能解释指定身份的允许／拒绝原因，不执行目标动作或签发该身份令牌，以便演练不能变成冒充用户。
74. 作为交付人员，我希望验收证据包含对应工程版本、预检、映射差异、权限和部署／导入状态，并区分仿真与现场证据，以便一份下载文件能解释当时真实发生了什么。
75. 作为交付人员，我希望所有工程和控制相关变更有可查询审计，以便版本、操作者、对象和结果能形成完整链路。

## Implementation Decisions

### 1. 基准、兼容与不变项

- 最新三工作台原型决定可见页面及交互组织；领域词汇表和已接受 ADR 决定数据、权限与运行安全语义。两者冲突时记录差异并明确处理，不暗中删功能或用演示结果覆盖安全约束。
- 沿用现有 Go 后端、鉴权体系、设备接入、命令结果、历史存储和项目包机制；不另起第二套服务、设备合同或权限引擎。
- 保留现有 React 应用，不将其删除或迁移作为本规格的前置。
- 本规格针对 PC H5，包括桌面与 10.1 寸触摸屏。正式模式使用现有工作台入口；预览是隔离模式，不靠接口失败或数据库为空自动进入。
- 将原型页面与关键状态建立可追溯基线。开发过程不得通过修改原型或改变对比 DOM 来制造验收通过。

### 2. 已有能力与需要补齐的范围

以下是当前代码的接入基线，不是“所有能力已验收”的声明。

| 能力 | 当前基础 | 本规格中的工作 |
|---|---|---|
| 对象、模板、成员、复制、批量接入 | 已有 API 和相关测试 | 接通统一上下文、持久化和跨页一致性，不重建 CRUD |
| Profile、通道、映射、L1/L2/L3 | 已有接口与安全校验 | 补齐原型状态映射、差异说明及失败路径 |
| 手动写值、Profile 命令、回读结果 | 已有统一结果和请求去重机制 | 前端统一消费，核实质量、时间、取消/断线和并发边界 |
| 历史、导出、告警、交接 | 已有主要 API | 补齐原型粒度、保留期元信息、按层查询和生命周期表现 |
| 决策表与状态机 | 已有草稿、发布、模拟、执行/启用 | 保留安全机制，补足显式作用范围和统一执行记录 |
| 画面定义与继承 | 已有结构化文档、版本校验和同类层应用 | 总览与配界面使用同一文档、同一渲染语义，取消预览/真实两套常驻行为 |
| 项目包、版本、预检、导入、回退 | 已有主体实现 | 接通真实交付流程、统计、证据和恢复策略 |
| 项目上下文 | 已有 Site、版本、复用来源等基础 | 不能把这些接口直接当成完整项目目录；补齐授权项目目录、工程身份与运行实例关系 |
| 今日统计 | 未发现覆盖原型整套口径的专用查询 | 增加后端统计契约、质量覆盖与时间边界 |
| 今日执行 | 已有规则、状态机和调度的分散记录 | 建立统一、可分页、按项目/层/日期查询的投影，不重造执行引擎 |
| 独立部署记录 | 未发现对应的独立记录 API | 建立版本→目标实例的持久化记录；发布/导入接口不能充当部署成功证明 |
| 聚合点 | 已有配置和按查询/保存计算 | 增加不依赖 HTTP 查看动作的运行时采样；未核实为已具备此能力 |

### 3. 统一项目与数据来源

- 项目目录至少提供稳定项目身份、名称、访问范围、工程版本、依赖和运行实例关联。项目与 Site 不能简单视作同义词。
- 同一现场运行实例只承载一个确定项目内容；多个 Site 不等于同时运行多个独立工程。项目菜单用于选择工程上下文，不自动新增跨站控制能力。
- 所有项目／层相关读取与写入明确携带或由服务端可靠解析作用范围；禁止按当前 URL 名称、中文标签或浏览器缓存推断写入对象。
- 三工作台共享同一工程真相来源。总览设备、已保存画面、交付统计和证据不得继续由互不关联的前端数组维护。
- 项目切换清理或隔离运行查询、编辑状态和在途请求；迟到响应不得覆盖当前项目。未保存修改在离开前明确保留或放弃，不能默默提交。
- 写入响应返回持久化身份及版本信息；前端刷新读取到的新状态才是跨页面显示的来源。工程写入具备冲突检测，不依赖最后写入者覆盖。
- 正式登录、令牌和预览状态分离。预览模拟身份不能生成真实会话，也不能覆盖已有真实令牌。

### 4. 总览、统计与历史契约

- 总览数据模型包含当前层的指标、设备／成员、拓扑绑定、告警摘要、趋势、运行摘要、今日执行与交接。可由现有 API 组合，但范围、时间和质量必须一致。
- 原型的固定演示值改为模型属性、聚合点、执行投影或统计结果。任何默认值只用于未配置界面结构，不用于伪造现场观测。
- 统计明确项目时区、日期区间、单位、采样来源、有效覆盖比例及更新时间。夏令时切换不能简单按固定 24 小时假设。
- 电量优先使用有效累计表计并处理复位／回绕；只有工程明确声明时才由功率积分。运行时长来自有效运行状态变化，缺失段不默认一直运行。通信成功率说明分子、分母和窗口；新鲜度基于可信观测时间，不能用页面刷新时间计算。
- 统一执行投影包括来源类型、策略/过程身份及版本、目标、触发时间、状态、原因、关联命令和回读结果；区分待处理、执行中、完成、跳过、失败及结果未知。重启和重复事件不得产生重复执行事实。
- 历史保留现有查询／导出能力；原型中的原始采样、展示粒度、窗口聚合须有明确映射。返回实际粒度和截断信息，不通过插值填出接口没有的数据。
- 数据质量事件、迟到数据和缺失区间须能够解释图表断点；补到的历史不得改写既有决策证据。

### 5. 命令、告警与权限

- 所有可写操作走现有统一命令与授权链路；请求身份绑定目标和参数，同一身份不同目标／参数冲突必须拒绝。
- 复用唯一命令结果来源，页面和节点上的结果字段只能是投影，不能各自维护不同结论。
- 回读确认要求符合时间、质量、目标和容差。只有已下发无反馈时保留“已下发未确认”；超时或确认无法完成时显示“结果未知”，不自动重试物理动作。
- 服务器逐请求校验角色、动作、对象范围、依赖与安全条件；未声明路由默认拒绝，引用的点位/目标也必须校验，不能只检查父对象。
- 告警接手、维护/关闭、条件恢复和再次触发分别处理；真实模式不开放一个“标记恢复”按钮来覆盖真实故障条件。需要人工确认恢复的业务必须有独立权限、语义和审计。
- 权限演练是只读授权解释，不执行命令，不更换当前会话身份。正式系统不得保留任意用户模拟入口作为后门。

### 6. 设计六步、画面与聚合

- 复用合法层级、设备模板、Profile 匹配和批量导入校验，保存／应用／验证明确分开。批量部分失败返回逐项结果，成功项与失败项不能互相冒充。
- Profile 切换使旧映射、验证依据和相关可操作性重新评估。L3 安全验证必须满足声明、动作权限、对象范围、显式确认和回读限制。
- 决策表扩展缺失的本对象／含下级作用范围，同时保持有序首命中、非嵌套 AND/OR、持续、时间窗、序列延时与回读语义。模拟与真实执行复用校验/评估逻辑，但模拟不能触达设备写入。
- 规则、状态机、计算点和虚拟输入保持既有职责，不引入任意脚本执行或另建控制旁路。
- 聚合采样由后端运行服务驱动。瞬时点随采样更新，窗口点在关闭时产生结果，并保存成员、覆盖、质量、观测时间和窗口依据；定义保存或读取不再是唯一产值触发方式。
- 配界面与总览共享结构化画面文档、绑定解析和块渲染规则。保存草稿只影响编辑预览；原型的“保存本层”作为明确应用该层画面定义的操作，不能与其他工程草稿保存混淆。
- 自动绑定块按当前层和能力推导；显式绑定按稳定身份与声明范围解析。继承来源、未绑定项、冲突与应用结果可见。
- 原型占位的全局工具页只保持导航契约。本规格不凭占位标题发明通信报文分析器、完整报警类型设计器或容量规划产品；涉及已有后端能力时沿用其既定界面范围。

### 7. 发布、导入、部署与证据

- 原型的普通“发布版本”必须在预检阻断时停止。当前后端存在确认后继续冻结的能力：若保留给管理员，则只能作为显式的非可交付快照，不得通过同一个按钮绕过原型门槛或把该快照标为可部署。
- 项目包依赖来自工程实际使用的行业包和 Profile，不因顶栏开关被简单删掉；停用仍被工程使用的依赖须拒绝或进入明确的不可用状态。原型模拟开关不能决定真实包内容。
- 导出与导入复用既有格式校验、引用重写、凭据/运行态剥离及失败回收。跨实例导入不携带旧命令、自动控制启用状态或个人令牌。
- 本页“导入当前工程到新实例”的闭环要求存在已发布版本。导入外部有效包可以是另一入口，不以“本机曾发布”作为跨实例导入的错误前置条件。
- 最小部署记录至少包含记录身份、项目、不可变版本、目标运行实例、发起人、时间、执行状态和结果原因。记录必须来自后端配置应用与验证事件，不由页面直接写“成功”。
- 本规格实现受控的本地／目标实例应用与记录，不新增任意远程地址部署、远程 agent 编排或跨站批量控制。目标注册与远程编排超出本次最小闭环。
- 导入、重绑、采集恢复与投运分开。界面上的“运行中”必须有当前实例采集或运行健康依据，并明确该状态不代表已授权自动控制。
- 回退先校验所有包内资源的恢复能力；已有计算点／虚拟输入不支持回退的限制不能被前端隐藏。原型闭环涉及这些资源时，应实现受控配置恢复或给出可追溯的阻断，不能虚报回退成功。
- 证据使用当前项目、版本和权限范围的同一快照，包含预检、映射差异、依赖、导入／部署状态、权限解释及相关审计。下载格式不是业务事实：可保留 ZIP，但其清单须覆盖原型 JSON 的信息，并可机器校验。
- 仿真证据、软件测试和真机签收分开标记；即使所有自动化通过，也不自动标记现场已验收。

## Testing Decisions

### 主测试接缝（推荐，待用户确认）

以现有 **浏览器工作流 → 同源 HTTP API → 真实 Go 服务 → 隔离测试存储／设备模拟器** 作为主要验收接缝。通过用户在三工作台中的操作观察持久化、实际查询和命令结果，而不是只检查 Vue 文件包含某段文字。

已有的路由授权、命令安全、历史范围、画面配置、项目包和状态机集成测试继续作为支撑。纯算法测试只补在统计、范围解析、去重和状态转换等真实边界处；不另建一套与生产逻辑分叉的测试引擎。

### 什么算有效证据

- 在真实模式启动产品；测试明确断言未进入预览 resolver，数据来自已知测试实例的 HTTP 响应。
- 不修改页面 DOM、CSS 或业务值来凑原型截图。允许在测试后端预置固定工程、冻结时钟、约束字体与视口，以保证可比较性。
- 点击、键盘输入、表单保存、错误恢复和跨工作台切换均通过可见控件完成；不使用强制填值掩盖输入框高度为零、遮挡或禁用等缺陷。
- 观察的是返回结果、持久化状态、查询可见性和模拟器实际收到的请求，不是 mock 是否按预定函数返回成功。
- 每项原型交互都标记“已有并验证／待补齐／仅原型占位／已确认差异”，不能以测试总数量证明全量 1:1。

### 必须覆盖的端到端场景

1. 新建工程→建立台账→绑定设备→L1/L2 验证→保存画面→总览显示→发布／导出；刷新和重启后仍成立。
2. 在同一项目中新增设备或修改画面，三个工作台与证据显示相同身份、版本和统计；切到另一项目不泄漏状态。
3. 双会话编辑同一配置，旧版本提交被拒绝；切页后的迟到响应不能覆盖新项目或给出错误成功提示。
4. 未绑定、离线、过期、无权限、超时、空记录和真实零值分别渲染；无效观测不触发安全条件或补零。
5. 设备命令接受后分别走新鲜回读成功、错误回读、无回读、断线、拒绝；重复请求只执行一次，冲突请求被拒绝。
6. L3 默认不写；缺少声明、权限、范围或确认任一项均拒绝，允许时模拟器只收到声明的安全操作。
7. 决策表在相同输入下模拟与真实评估选择同一规则；持续、时间窗、作用范围、序列延时及读取质量均参与判断；模拟器执行与真实命令链路隔离。
8. 无浏览器连接时，聚合点仍持续产生；窗口关闭、成员缺失、过期和服务重启均有可解释的结果。
9. 今日统计覆盖时区日期边界、表计复位、运行状态缺口和重复事件；今日执行可以追溯到策略版本及关联命令。
10. 告警接手不恢复条件；真实恢复进入历史，再次触发次数与身份正确；定位和历史链接保持对象范围。
11. 预检失败阻止普通发布；依赖不匹配拒绝导入；导入失败后存储无可运行残片。
12. 在另一隔离实例导入项目包→重新绑定模拟器→检查采集恢复→生成真实部署记录；全程不重放旧命令，不自动启用控制。
13. 回退验证配置版本改变但历史、告警、审计和命令记录不倒退；不支持的资源得到明确阻断。
14. 权限矩阵、拒绝反馈、服务器逐请求校验和只读权限演练一致；隐藏按钮不是唯一保护。
15. 导出证据能复算其版本、统计和状态；受限用户无法导出超出对象范围的内容。
16. 原型预览模式完全不发真实业务写请求；正式模式遇错完全不读原型数据，预览令牌在真实接口不能获得权限。

### 视觉与交互验收

- 主视口为 1440×900 和 1280×800；复核 1024×768 与 375×812 的适配及操作可达性，不据此宣称小程序兼容。
- 覆盖三工作台的所有已实现状态，而不只截首页：各层总览、外观、历史、告警、操作、六步及工作区、块绑定、项目菜单、项目包、预检、导入重绑、回退、权限和依赖错误。
- 固定测试数据与原型对应场景，保留并排截图、关键样式/位置对照和差异清单。字体抗锯齿、真实内容长度和明确安全提示的差异必须解释；不可用局部硬编码高度掩盖缺失内容。
- 页面不得出现无法点击的真实输入区、原型有但不可达的路由、正文遮挡、意外页面横向溢出或未处理异常。

### 完成判定

同时具备：原型状态矩阵无未说明遗漏、真实端到端关键路径通过、刷新／重启／并发／故障路径通过、权限与写入安全回归通过、可审查视觉证据齐全。正式展示不依赖演示数据。任何未满足项保留为未完成，不宣称“全部 1:1”。

## Out of Scope

- 重新设计三工作台、自由拖拽大屏、任意脚本、BI 报表中心或另建一套 React/后端应用。
- 把每个原型占位页都扩展为完整业务产品，或把工艺图装饰性控件自动升级为新的三维编辑器。
- 小程序/App 原生发布、跨站远程控制和通用远程部署编排。
- 模拟状态直接写入正式设备、任意身份切换、绕过互锁或自动恢复控制授权。
- 用演示包、前端假数据、HTTP 200 或仿真通过替代现场部署证据和真机签收。
- 批量重构无关模块、清理全部历史技术债、重写 Git 历史。
- 自动提交、推送、创建 PR、连接真实设备或执行真实物理写入；这些操作需要另行授权。

## Further Notes

- 用户以“1、2、3 都按建议”确认：原型外增强控件不进入复刻页面；原型明确占位的入口及页面按原样保留；预览数据跨页联动并在刷新后恢复统一基线。这些约定不授权扩大真实现场控制能力。
- 已接受 ADR 中与本规格直接相关的主题：三工作台、步骤驱动设计、按层 SCADA、块目录与声明式绑定、四段式规则、Profile 驱动接入、运行时聚合点。保持其中的职责与安全语义，不把旧实现限制当成最终产品需求。
- 需要在实施前确认的规格差异：正式发布与管理员强制冻结的边界、目标实例部署记录的最小范围、权限演练在正式系统的可见角色，以及原型显示粒度与后端实际采样／聚合口径。本文已给出保守推荐，不授权实施者自行扩大控制权限或远程执行范围。
- 推荐纵向推进：统一上下文与数据源→真实只读总览/历史→设备接入与受控命令→策略/状态机/持续聚合→画面保存到总览→项目包与部署记录→全状态验收。25 张本地执行票按可独立验证的用户闭环划分，仅启动阻塞依赖已完成的票；本地集成工作已另获用户指令。
- 项目的 issue tracker 已配置为公开 GitHub 仓库 `taidai/fastiot`，分流标签为 `ready-for-agent`。遵守项目的发布授权边界：用户单独确认后才创建 issue；未确认前保持本地草案，不写评论或发布凭据、环境路径、实际设备地址等私密信息。
- 既有本地调试凭据进入版本历史的问题是正式运行前的安全检查项。凭据轮换、启动配置修复和历史处理需要单独确定范围，本规格不授权自动清理或重写提交。
