# 上边栏收敛为总览、设计、交付三个大项

状态：accepted（2026-11-21）

接入与策略原本是交付工作台里的两个分组，和它们配置的对象分居两处：选设备要回台账，配策略又去另一个分组。顶栏收敛为三个大项——总览、设计、交付。设计页默认落在台账树，接入（绑定设备与点位）与策略（决策表、状态机、分配）都从选中节点进入；交付页只留交付资产（项目包、版本、回退、部署）与系统（账号、审计、行业包）。跨节点的站点工具放在现场根节点的面板里，按接入、计算、诊断分组；树下不设工具栏。

## Considered Options

- **保留两个工作台 + 五个交付分组**：任务分组和对象分组各说各话，同一台设备要在两处找。
- **把系统放客户面**：审计与行业包是交付关注点，客户面只应看现场。
- **四个大项（设备/策略/交付/系统）**：策略离开对象，又变成一次重新选择。
- **三个大项（采纳）**：代价是"设计"这个名字覆盖建模、接入、策略三件事；收益是任何时候都在一个对象上下文里工作。

## Consequences

- ADR 0002 的分组方式被本 ADR 取代；三个工作面仍然成立，但表现为节点能力，不再是导航分组。
- 账号与权限一页两套措辞：交付 → 系统进入是交付视图；总览页右上角进入只显示人员、可查看范围与可执行操作（ADR 0001）。
- 设计工作台的具体形态由 ADR 0007 定义：按使用步骤牵引，而不是按节点类型铺开全部分区。
- 新建只允许合法子类型：现场与区域可建区域、业务单元、设备；业务单元只能建设备；设备不能再建。未绑定的设备在可操作性、数据与诊断里一律显示不可用或未接入，不显示想象中的值。
- 总览不是三页任务，而是按层的 SCADA 大屏，见 ADR 0008。
