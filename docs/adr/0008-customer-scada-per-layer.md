# 总览工作台是按层的 SCADA 大屏，告警统一到铃铛

状态：accepted（2026-11-21）

总览工作台（客户视图）不按页签组织，也不复制交付步骤。左侧是悬浮、可收起的台账树；点任意一层，右侧换成该层的 SCADA 大屏：实时指标、下级设备、工艺/能流、最近数据、趋势、操作与历史。大屏内容来自交付人员在"配界面"里保存的该层配置（配置方式见 ADR 0009）。所有告警只在上边栏右上角的铃铛（告警中心）处理，不散落在各层。

## Considered Options

- **三页模块（总览/画面/报警）**：找得到功能，但每层要重新找对象，不像 SCADA。
- **值班台三问（现在怎么样/需要我做什么/上一班留下什么）**：适合交接，但不是现场大屏。
- **悬浮台账 + 每层大屏 + 告警中心（采纳）**：代价是每层要配界面；收益是客户看到的就是这一层。

## 总览放哪些东西

只放"看现场、处置现场"，不放"配现场"；每一层是同一套，下钻只换对象。清单依据见 [IoT 共性场景研究](../research-overview-common-problems-2026-11-21.md)。

- **可信度**：状态条（更新于、通信、数据质量、采样）；台账树上每层的已接入设备数。回答"这一屏的数能不能信"。
- **对象与数据**：台账树（可搜索、可收起）；指标条（当前值＋目标值/阈值＋单位，不是裸值）；工艺图或能流（一条链上的多台设备同屏）；设备清单（通信、运行、维护三种状态分列）；最近数据表（带质量列）；趋势。回答"这一层有什么、现在怎么样、值怎么变"。
- **事件与处置**：本层告警块与顶部告警条；右上角铃铛（唯一总入口，角标＝待接手数）；设备层的操作抽屉与操作记录（待回读／已回读／结果未知）；今日执行（自动化今天几点触发、完成／跳过／失败、跳过原因）。运行摘要管连续量（今日电量、运行时长、通信成功率），今日执行管离散事件。回答"出了什么事、谁接手、动作结果如何"。

不进来的：

- 建模、通道、点位表、模板、设备验证、聚合定义、决策表/状态机编辑——属于设计工作台。
- 数据保留、版本、项目包、账号、审计、行业包——属于交付工作台。
- 拖拽看板与 BI、公开分享链接、App、地图与实时位置、脚本编排——明确不做，或属行业包。
- 历史导出与报表中心——在历史页里做，不占总览首屏。

判断某样东西该不该进总览，用三个筛子：随现场变化吗（配置不进）；支撑一个当下的判断或动作吗（分析与报表不进）；属于"这一层"吗（跨层的只留铃铛）。

## Consequences

- 客户只看到已绑定设备；未绑定设备不出现在台账与大屏，整层都没有已接入设备的下级对象也不出现。
- 大屏由四段组成：状态条（更新时间、通信、数据质量、采样）、指标条（6 格，点任一格进历史）、主区（工艺图／成员／下级对象＋设备清单＋最近数据表）、右栏（本层告警、趋势、运行摘要、今日执行）；设备层多一张操作记录。
- 设备清单逐台显示通信、运行、维护三种状态与数据新鲜度；指标条带目标值或阈值。层的聚合数字不能盖住单台离线或"在线但停机"。
- 大屏的指标、设备、趋势块由该层"配界面"决定；未配置时给默认块。
- 告警中心是唯一告警入口：角标等于待接手数；可以确认接手、定位到设备、看历史。各层大屏的告警条与告警块只列本层子树内的告警，总数仍以铃铛为准。
- 历史与操作以右侧抽屉打开，不离开当前层；历史数据是整屏表格：时间范围、粒度、数据表/曲线、导出 CSV，不用小抽屉。表头列随对象变化（设备看本机点位，站点看汇总序列）；表头标出当前保留期，缺失段不补值。
- 确认接手不等于设备恢复；超时未回读显示"结果未知"，不伪装成功。
