# 聚合结果是节点上的计算点，瞬时与窗口分开

状态：accepted（2026-11-21）

聚合定义挂在作用范围的节点上，运行时产生一个同节点的只读**聚合点**：值、单位、质量、时间、窗口区间与参与成员。瞬时聚合随采集周期计算，窗口聚合在窗口关闭时计算；两者都写回节点，画面、历史、报警与规则按同一种点使用。窗口聚合可以作为决策表或状态机输入，但绑定处必须显示"滞后 ≤ 一个窗口"；联锁与保护只能绑定瞬时点。现在"按查看计算"的实现不满足这个定义：它只在 GET 时写一次 `easyemsAggregateValue`，没人在看就没有值。

## Considered Options

- **保持按查看计算**：实现最省，但历史按谁打开过页面而断，规则读到的是最后一个查看者留下的值。
- **查看时计算并缓存**：只是把同一个问题藏起来，仍然没有稳定的观测节拍。
- **运行时采样（采纳）**：代价是要有采样循环、失败与过期语义；收益是聚合点真的是实时数据，能被规则与历史依赖。

## Consequences

- 瞬时聚合的观测时间取参与成员的最新时间；窗口聚合取窗口结束时间，并记录有效成员/总成员。
- 无值不补零：成员过期或缺失时按已配置的质量策略降级或标不完整。
- 规则绑定窗口聚合时必须显示滞后；联锁/保护的绑定点位校验要拒绝窗口聚合。
- 历史按节点 id 记录聚合点，不再依赖是否有人打开页面。
