# 以原型为界面基准，取消预览模式，只保留实时路径

状态：accepted（2026-11-26）

界面一直有三份"事实来源"：最终原型（`frontend/prototype/overview-hd/` 三份 HTML）、ADR/spec 的后续决策、以及实现。三者不完全一致，导致"以谁为准"每次都靠临时判断，验收时也说不清某处差异是有意还是遗漏。

## Decision

1. **原型是界面基准**：形状、层级、流程、文案以原型为准。ADR/spec 只在两种情况下压过原型——原型没有画到的部分，以及安全与领域语义（例如"未验证不算接入"，ADR 0011）。
2. **取消预览模式**：删除 `?preview=1` 这条复刻路径及其数据源（`src/api/preview/*`、`OverviewPreview.vue`、`*.preview.browser.mjs`）。`spec:149` 要求"取消预览/真实两套常驻行为"，此前的做法是保留两套并接受分叉（`25.md:59`），本 ADR 改为直接收敛为一套。
3. **"建现场"= 在唯一项目根下新建 Site**：运行实例只承载一个项目（`project_context.go`），因此不再使用"新建/切换项目"的措辞，第一步的文案与交互同步改为"新建现场"。
4. **三维能流暂不实现**：后端没有能流聚合能力，现有"能流"由每台设备前三个点位拼成。原型的三维视图记为示范，不进入实时路径；做能流须独立立项。

## Considered Options

- **ADR 优先、原型降为视觉参考**：文档更自洽，但用户已明确以原型为准，且原型是唯一完整画过所有状态的东西。
- **保留两条路径并明确分工（预览=复刻面、实时=产品面）**：风险最低，但两套组件与两套数据长期漂移，且预览会持续长出原型没有的东西。
- **只保留实时路径（采纳）**：代价是失去离线演示能力，原型对照必须起真实后端；收益是只剩一套界面，"一不一致"只有一个判断对象。

## Consequences

- `src/api/preview/*` 及其测试下线；`OverviewPreview.vue` 删除；涉及预览的浏览器脚本作废或在真实后端上重写。
- 原型对照的验收方式变为：起真实后端 + 种子数据，按原型状态逐条比对；`25.md` 中"预览跨页共享、刷新回基线"的验收项随之失效，需要在该票里标注。
- 安全语义仍按 ADR 0011：设备只有在必需点位验证通过后才显示"已接入"，界面分「未绑定 / 已绑定待验证 / 已接入」三态。
- 预览一次性消失后，任何"演示需要"都要用种子数据解决，不允许再引入第二条渲染路径。
- 按原型移除"指标条点击进历史"：ADR 0008 曾明文承诺指标条六格点任一格进历史，但原型没有这条交互。依决策 1 以原型为准移除，属有意差异；历史改由今日统计的 24 小时柱打开右侧抽屉。
- 项目根不作为客户层出现：总览台账从 Site 起（原型共六层），默认选中层也是 Site；选择项目根的调用被忽略。
