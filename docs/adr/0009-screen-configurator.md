# 配界面是块目录加声明式绑定，不做自由画布

状态：accepted（2026-11-21）

配界面（设计第 5 步）不是制作大屏，而是给台账树的每一层选块、把块绑到该层的物模型、按槽位排版。产物是一份结构化画面文档：`{layer, slots, blocks:[{type, binding, span}], version}`。保存即对该层的客户视图生效；发布时编译成现有画面格式（`internal/genscreen` 的 HTML 与 `data-fastiot-point` token），随项目包走，导入重绑后仍能渲染。

块目录封闭：状态条、指标组（≤6，每个带目标值或阈值）、工艺图／能流、设备清单、成员、下级对象、设备数据（实时／参数页签）、最近数据、趋势（≤4 条序列）、告警、今日执行。行业包只能提供默认模板与拓扑默认值，不能新增块类型；EMS 的能流是"工艺图"块里的一份拓扑数据。

绑定声明式，指向物模型概念而不是字段：本层或下级设备的属性与聚合点、子树设备、成员角色、本层拓扑、能力契约。默认块由节点类型推导：现场＝工艺＋设备清单，区域＝下级对象＋设备清单，业务单元＝成员，设备＝设备数据＋最近数据。

版式是槽位不是画布：固定主区（可两栏）、右栏、底部，块声明占 1 或 2 列；三种模板对应现场、区域、设备。拖拽只在槽位内换顺序，不做像素定位。未保存的层继承最近祖先的配置，并在界面上标出继承自哪一层；"保存并应用到同类层"避免逐层重复。

## Considered Options

- **拖拽画布／大屏设计器**：表达力最强，但会把产品变成 BI，且交付物无法保证两层一致。
- **每层手写 HTML 或让 AI 生成**：就是现状；交付人员改不动，换现场无法稳定复现。
- **固定模板、不可调整**：实现最省，但八个行业的关注点与不同层级装不下。
- **块目录＋声明式绑定＋槽位版式（采纳）**：表达力受限，但每层可配置、可继承、可进包、可重绑。

## Consequences

- 第 5 步直接渲染客户会看到的那一屏（真实数据），块上开配置面板，不再有单独的预览页。
- 每块可配的绑定只有这些：指标组选 4–6 个指标；最近数据选列与 3/5/10 行；趋势选 1 条序列；设备清单选列（设备列固定）；设备数据选页签；工艺图选是否显示次要信息。其余块（状态条、告警、今日执行、操作记录、成员、下级对象、运行摘要）自动绑定，不给空开关。
- 预置块不用配：状态条、告警、今日执行、设备清单、成员、下级对象都从子树与能力契约推导；要配的只有指标、拓扑、最近数据与趋势的绑定。
- 设备层的操作不占块，从操作入口开抽屉；下发后显示待回读／已回读／结果未知。
- "配界面完成"的判定：每层已保存，或明确继承自某层；不静默生效。
- 超出块目录的诉求（自定义图表、任意布局、第三方组件）不做，与"不做拖拽大屏与 BI"一致。
- 现状缺口：代码里只有生成的画面 HTML（`internal/genscreen`），没有块配置器与继承逻辑；本轮只定形态。
