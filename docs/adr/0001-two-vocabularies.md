# 同一产品保留客户视图与交付视图两套措辞

FastIOT 只有一个应用，但有两类读者：交付人员配置通道、Profile、决策表，终端客户只看现场状态并做受控操作。我们决定让两者看到**同一份数据、不同的措辞**——交付视图保留内部概念，客户视图不出现内部术语、实现限制和交付配置动作——而不是抽一套对谁都中性的词汇。

## Considered Options

- **统一成中性词汇**：交付人员会失去精确表达（"通道"只能叫"连接"，"聚合"只能叫"统计"），配置界面变得含混。
- **拆成两个产品**：需要两套部署、两套权限与两套发布节奏，与"一个应用、共享项目与运行事实"的产品结构冲突。
- **同一产品两套措辞（采纳）**：代价是每个页面要维护两种文案，收益是两类读者各自不被对方的概念干扰。

## Consequences

- 新增面向客户的界面元素时，必须回答"这句给谁看"，并在客户视图中回避术语表列出的内部词。
- 术语边界写在 `GLOSSARY.md` 的「客户视图 / 交付视图」条目，改文案时以它为准。
- 客户视图的用词不能靠隐藏组件实现——页面本身属于客户工作台，就必须说客户的话。
