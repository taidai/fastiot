# 接入以 Profile 为唯一来源，验证按读写风险分级

状态：accepted（2026-11-22）

接设备不再把“选型号”当成一个名称选择。Profile 是接入的唯一来源：声明采集点、寄存器地址、数据类型、倍率、单位、枚举、读写方向、必填/可选、命令及参数约束，以及哪些点允许安全写回读。自动匹配、批量套用、CSV 导入和验证都从同一份 Profile 推导，不再各自维护一套点位。

接入页采用步内工作区：顶部保留“型号 → 通道 → 点位 → 验证”的进度，下面只展开当前一段；上一步仍可回看，批量接入先出差异清单，再逐台验证。

验证分三级：L1 连通，L2 全部必需点位读值与质量，L3 安全点写回读。L3 默认不执行，必须选择 Profile 明确允许的安全点并确认后才可执行；未声明可写的设备不得以写回读通过冒充接入完成。

## Considered Options

- **四段同屏展开**：信息完整，但接入页面很长，批量接入时难以定位问题。
- **型号只作标签，点位人工维护**：实现简单，但同一映射会在型号库、自动匹配和验证中各写一份，容易不一致。
- **所有设备都做写回读**：能证明写链路，但会把安全验证变成现场控制。
- **Profile 单一来源＋步内工作区＋分级验证（采纳）**：实现约束更强，但接入过程可解释、可复用，且不越过“验证不是控制”的边界。

## Consequences

- 必需点未映射或读取失败，设备仍标未接入；可选点缺失要单列，不计入通过数。
- 验证结果必须带时间、操作者、级别和失败原因；不能只给一个“通过”。
- 批量只生成映射草稿，不批量伪装成功；站号冲突、通道离线、必需点缺失逐台显示。
- 通信报文、重连、丢包和在线率属于运行期诊断，不进入接入工作区。
- Profile 可随项目包交付，但现场通道、地址和凭据仍需重新绑定。
