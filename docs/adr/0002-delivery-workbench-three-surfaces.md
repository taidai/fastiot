# 交付工作台按三个工作面组织，项目是上下文

状态：部分被 ADR-0005 替代（2026-11-21）——三个工作面与项目上下文保留，分组方式以 0005 为准。

一句话定位要求底座能用物模型描述对象、用决策表和状态机表达策略、用项目包保证交付可复现。据此，交付工作台只保留三个工作面——接入、模型、策略——加一个交付资产工作面；客户工作台仍是总览、画面、报警三页。"项目"不是第四种任务，而是全局上下文：顶栏切换、空项目时引导新建或导入。"交付验收"不再是一个检查中心：项目包、版本、回退、部署归入交付资产，门槛与预检降为各页就地检查，设备验证归入接入。

## Considered Options

- **保留按旧 EMS 任务（J1–J6）划分的六个分组**：分组被行业包塑形，底座的物模型没有落点。
- **把验收清单做成独立中心**：与规格"不新建中心"冲突，竞品也没有等价界面可参照。
- **三个工作面 + 交付资产 + 项目上下文（采纳）**：代价是交付面要改分组与页名；收益是每个页面都能回答它服务哪一层。

## Consequences

- 模型页是唯一建模入口；EMS 包在同一页面增加能源单元类型、接线与资源集群，不另起"能源设备"组。
- 状态机用表格式编辑（状态、事件、守卫、转移、等待反馈），不做画布；运行时监视视图可参照 SFC。
- 项目包仍是唯一可版本化的交付物；回退保留（只回工程配置，不回历史与命令），三方升级对照移出界面。
- 2026-11-20「不重做信息架构」的边界只约束客户工作台；本 ADR 改变的是交付工作台的分组，不涉及客户面。
- 新增页面必须先回答它属于哪个工作面，答不出就不做。
