# 模型页采用台账树：先搭骨架，后绑设备

状态：accepted（2026-11-21）

模型页以"现场 → 区域 → 业务单元 → 设备"的台账树为默认结构。父节点只做归属与汇总，不产生数据、不下发命令；业务单元通过成员角色对外提供能力；设备才有通道与点位。设备可以先建成占位，未绑定前显式标记、不计入可交付、不出现在客户视图。

## Considered Options

- **所有节点都是同一种"组"**：界面好看，但引擎无法区分容器与可调度对象，EMS 分配和画面操作都找不到落点。
- **模板卡片墙（原型 B）/ 设备平铺表（原型 C）**：模板或设备各自有了落点，但初学者要同时理解"模板、实例、单元"三层才能开始；台账树把这三层放在同一棵树里按位置理解。
- **台账树（采纳）**：代价是每种节点要有不同的右侧面板与校验；收益是初学者能按现场直觉建骨架，交付人员仍可从设备跳到来源模板。

## Consequences

- 新建入口先问"建在哪一层"，设备占位允许长期存在，但必须显示"未绑定"。
- 交付统计与验收清单区分"已绑定/未绑定"；客户视图只显示已绑定设备。
- 模板不再作为顶层导航，而是从设备进入"来源模板"。
- **树是三个工作面的共同脊柱**：接入（绑定设备与点位）与策略（决策表、状态机、分配）都从选中节点进入，切换页面保留选中对象；而不是在三个互不相干的页面里各选一次设备。
- **策略挂在节点上必须声明作用范围**：设备/单元默认只作用于本对象；区域只能"含下级"。列表显示继承来源，不做静默继承。
- 站点模板（一键建整棵树）是后续独立决定，本 ADR 不预先承诺。
