# 决策表用四段式规则行，只做条件到动作

状态：accepted（2026-11-22）

一条规则由四段组成：**条件组**（AND/OR 一层，数值与布尔/枚举混用，含采集有效、运行许可、进行中）、**持续时长**（条件连续成立多久才算）、**时间窗**（常驻、每日时刻、时间区间）、**动作序列**（下发、延时、再下发，每一步都要回读与超时处理）。规则仍然有序、首命中、可模拟，模拟逐行给出跳过原因。

四段都可退化为最简：无持续＝瞬时；无时间窗＝常驻；单动作＝一条下发。条件组内不再嵌套括号。

## Considered Options

- **单条件行（原型旧版）**：一条“数值比较 → 动作”最好解释，但研究里的六个真实案例一个都复现不了——它们都以“采集有效＋许可＋未进行中”作前置，多数还要持续时长、时间窗与延时动作。
- **按场景分专用块（阈值块／定时块／联动块）**：每种场景简单，但交付人员要学多套模型，且跨场景的组合无处安放。
- **脚本或云函数**：表达力最强，但不可解释、不可验收，且越过“不写代码”的边界。
- **四段式规则行（采纳）**：一套模型覆盖阈值、定时、联动与序列动作；代价是规则行的编辑比单行复杂，需要模拟器把原因讲清楚。

## Consequences

- 条件值为无效数据时不等于“正常”：采集无效视为该条件不满足，并在模拟里写明原因，不补零、不沿用旧值。
- 持续时长与时间窗都在模拟器里可见（已持续多少秒、当前模拟时刻是否落在窗内），不允许只藏在后台。
- 动作序列每步都要回读；超时显示“结果未知”，不把请求当完成。去重（如“本日已申请”“每日上限”）写成布尔条件或动作前检查，不另设隐藏开关。
- 跨设备优化、预测与学习算法不进入决策表，由行业包提供；带过程记忆的设备过程仍由状态机表达。
- 决策表不引入变量、循环、外部调用；出现这类需求时先判断是否属于行业包，而不是给规则行加脚本能力。
