## 一、逐段推导

### 1. 物模型 = 对象分四层，交付面必须有建模落点

| 层 | 谁建 | 在哪建 | 如何复用 | 客户看到 |
|---|---|---|---|---|
| 设备模板 | 交付人员 | 建模 | 同类设备复制，只改差异 | 看不到 |
| 设备实例 | 交付人员 | 建模 | 引用模板与 Profile，自己的现场连接 | 设备名 |
| Unit / Unit 模板 | 交付人员（可选） | 建模 | 成员角色绑定多台设备 | 业务单元名 |
| Site / Area / Group | 交付人员 | 项目 | 组织归属与横向集合 | 站点、区域 |
| 能力契约 | 随模型声明，运行期求值 | 自动 | 决定"能不能操作、为什么" | 操作可用性 |

客户只看对象、数据与可操作性，看不到模板、Profile、契约（ADR 0001、GLOSSARY）。

**[现]** 点表模板（只装 Modbus 点位，`internal/appapi/templates.go`）、EMS 能源单元模型（`unitmodels.go`）、能力判定（`frontend/src/capabilities.ts`）。
**[应]** 通用属性／命令／事件、Unit 成员绑定没有界面；`deviceTemplate` 只在 API 类型白名单里，没有创建入口。物模型目前是点位表的附属语义，不是一个工作面。

### 2. 策略 = 两种可解释表达，一条不写代码的边界

- **决策表**适合"条件 → 动作"：有序、首命中、可模拟、可解释；不适合有过程记忆、要按步骤推进的事。
- **状态机**适合"设备过程"：状态、事件、守卫、转移、等反馈；不适合数值优化与跨设备分配——那是行业包的算法，交付人员只填参数。
- 边界到此为止；自由脚本与任意算法 **[否]**（规格 Out of Scope）。

**[现]** 决策表编辑器（`frontend/src/DecisionEditor.tsx`、`internal/decision`）。
**[应]** 通用状态机编辑。当前只有 EMS 柜体状态机硬编码在 `internal/decision/cabinet_state.go`，底座侧表达不了设备过程。

### 3. 可重复交付 = 项目包是唯一交付物

包内（`internal/appapi/project_package.go`）：节点与点位、画面（绑定 token 化）、依赖（行业包版本与 Profile 内容指纹）、被剥离的现场绑定、格式版本。地址、凭据、控制启动与运行数据不进包。

四个动作各是一件事：发布＝定版本；部署＝在干净实例导入并重新绑定现场；验收＝证据，不替代真机；回滚＝只回工程，不回历史与命令。

"交付两次结果一致"靠三件事：依赖版本锁定（不匹配拒绝启动，`industry.Open`）、现场秘密剥离（导入必须重绑）、稳定引用（节点 ref 与画面 token）。

**[现]** 导入导出、发布、回退、从已发布项目复用，都在"验收清单"页（`frontend/src/DeliveryWorkbench.tsx`）。
**[应]** 一个项目状态入口，回答"这个项目是哪个版本、依赖什么、部署到哪"。它现在没有独立位置。

### 4. 付费 EMS = 接缝在导航、依赖与数据

- 界面：带 `package: "ems"` 标记的页，未启用即不可达（`frontend/src/navigation.ts`）。
- 数据：EMS 对象就是普通节点，卸载不删数据（`internal/industry/industry.go`）。
- 权限：同一套角色与动作，包只增加页面，不新增权限体系。
- 没买：客户与交付都看不到 EMS 页，底座照常交付。

**[现]** 按站点激活的注册表，未购买时路由 409。
**[应]** 用户能看见"本站点启用了什么"。**[否]** 内置计费——授权发放属商务流程，软件只呈现启用状态。

### 5. 界面结构

| 工作面 | 页面 | 每页回答 |
|---|---|---|
| 总览 | 每层 SCADA 大屏（悬浮台账切换图层） | 这一层现在怎么样、有哪些设备、能不能操作 |
| 总览·查证 | 整屏历史表（时间范围／粒度／数据表或曲线／导出）；操作抽屉；告警统一在右上角铃铛 | 这个值怎么变、这次动作谁发的、出了什么事、谁接手 |
| 设计 | 步骤条：建现场 / 搭台账 / 接设备 / 配策略 / **配界面** / 交付（台账树提供对象上下文；每一层可配自己的总览） | 现在到哪一步、这一步要做什么、做完的标准 |
| 设计·步骤内工具 | 搭台账→模板库；接设备→通道/点位表/型号库/设备验证/通信健康与报文；配策略→聚合/计算点/虚拟输入/报警类型；交付→数据保留 | 这一步用到的工具就在这一步，不另设工具抽屉 |
| 交付 | 交付资产：项目包与版本 / 部署记录 / 版本回退 | 这份工程能否在别处原样跑起来 |
| 交付 | 系统：账号 / 审计 / 行业包 | 谁能做什么、本站启用了什么 |

结论：总览 1 块按层的 SCADA 大屏（悬浮台账切层、铃铛收告警）、设计 1 棵树 + 6 步牵引、交付 2 组页面。项目入口仍 **[应]**：顶栏的项目切换与新建/导入；行业包状态落在交付 → 系统。
OPC-UA 已从产品形态移除（2026-11-21）；`internal/appapi/opcua.go` 与验收证据仍在，删不删代码另行决定。
「不重做 IA」的边界只约束客户面：客户 3 页不变，变化全在设备与交付两个工作台（ADR 0005）。

## 二、与当前实现的冲突

1. **没有"新建项目／现场"入口。** 只能导入项目包；`NodeManager` 只有改、移、删，手册步骤 1 却要求从空白建工程。可重复交付的起点缺席。
2. **物模型没有工作面。** 模板只覆盖 Modbus 点表，Unit 只在 EMS；见 1.1。
3. **状态机只在 EMS 里。** 规格 US-06 与术语表承诺它是底座能力，代码只有柜体状态机。
4. **"交付验收"分组与规格冲突。** 规格明说不设独立交付检查中心，导航却有验收清单与设备验证两页，需要二选一。
5. **升级／回滚代码多于规格。** `project_upgrade.go` 的三方对照与回退被规格列为不做；要么承认它是"可复现"的一部分，要么关掉。
6. **付费包默认全开。** 站点没有决策记录时 EMS 即激活，安装只有 API 没有界面，买与没买在软件里没有区别。
7. **AI 生成画面不在这句话里。** 它是制作手段，不是形态要求；保留可以，但不能拿它替代物模型、策略与交付。

这些是实施缺口，不是未决方向：2、4、6 见 ADR 0004／0005／0003，3、5 见 ADR 0002，1 见 ADR 0005 的项目上下文。代码均未动。

## 三、明确不做

多租户与云端同步、边缘集群、拖拽大屏与 BI、自由脚本、独立检查中心与灾难恢复中心、内置计费、把竞品功能表当需求（`docs/reference-systems-review.md` §4–6、`docs/iot-platform-benchmark.md` 最终取舍）。

## 判据

一位交付人员能在界面里走完"建项目 → 接设备 → 建对象 → 配策略 → 发布包 → 在另一实例导入跑起来"，全程不写代码，产品形态就对了。
