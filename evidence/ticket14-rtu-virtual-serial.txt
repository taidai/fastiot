## 3. 样板进程经虚拟串口运行（CLI 级，仍是虚拟串口）

一台 `cmd/pumphouse` 进程，模拟站与主站各占用一对 pty 的一端，两端由一段纯字节桥连接
（相当于 socat 建立的成对 pty）。样板以 RTU 从站身份运行，通道地址是另一端的 pty 路径：

```
station=/dev/pts/0 bus=/dev/pts/1
...
2026/11/19 16:30:02 sample project ready (simulated device, NOT real hardware)
2026/11/19 16:30:02   level=54.7% pressure=0.08 MPa pump1=0 pump2=0
```

说明应用运行时确实从串口字节流取到了液位/压力/运行反馈，而不是进程内赋值。

链路计数（`GET /link`）：

```
运行 30 s 后      {"Requests":84,"Responses":84,...}
静默 6 s 后       {"Requests":87,"Responses":84,...}     <- 3 个请求被收下但不应答
解除静默 8 s 后   {"Requests":111,"Responses":108,...}   <- 24 个请求全部恢复应答
```

`Mute` 期间主站超时、调用方得到无效数据；清除后无需重启即恢复采集。

## 4. 证据分级

| 等级 | 本文件是否覆盖 |
| --- | --- |
| 虚拟串口 | 是（第 2、3 节，Linux pty） |
| 真实串口 | **否**（未连接任何物理串口） |
| 真机 | **否**（未连接任何真实控制器） |

虚拟串口没有电气层，也不覆盖多站总线冲突、波特率误差和现场固件差异。第 2、3 节的通过
不能写成真实串口或真机的通过。
